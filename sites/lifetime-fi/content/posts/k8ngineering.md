  <h2 style="white-space:pre-wrap;">The Kubernetes network model </h2><p class="" style="white-space:pre-wrap;">specifies: </p><ul data-rte-list="default"><li><p class="" style="white-space:pre-wrap;">Every pod gets its own IP address.</p></li><li><p class="" style="white-space:pre-wrap;">Containers within a pod share the pod IP address and can communicate freely with each other. </p></li><li><p class="" style="white-space:pre-wrap;">Pods can communicate with all other pods in the cluster using pod IP addresses (without <strong>NAT</strong>).</p></li><li><p class="" style="white-space:pre-wrap;">Isolation (restricting what each pod can communicate with) is defined using network policies </p><p class="" style="white-space:pre-wrap;">As a result, pods can be treated much like VMs or hosts (they all have unique IP addresses), and the containers within pods very much like processes running within a VM or host (they run in the same network namespace and share<br> an IP address).  </p></li></ul><h2 style="white-space:pre-wrap;">What are Kubernetes Services?</h2><p class="" style="white-space:pre-wrap;">Kubernetes <strong>Services </strong>provide a way of abstracting access to a group of pods as a network service. The group of pods is usually defined using a <strong>label selector</strong>. Within the cluster the network service is usually represented as virtual IP address, and kube-proxy load balances connections to the virtual IP across the group of pods backing the service. The virtual IP is discoverable through Kubernetes DNS. The DNS name and virtual IP address remain constant for the life time of the service, even though the pods backing the service may be created or destroyed, and the number of pods backing the service may change over time. </p><p class="" style="white-space:pre-wrap;">Kubernetes Services can also define how a service accessed from outside of the cluster, for example using </p><ul data-rte-list="default"><li><p class="" style="white-space:pre-wrap;">a node port, where the service can be accessed via a specific port on every node </p></li><li><p class="" style="white-space:pre-wrap;">or a load balancer, whether a network load balancer provides a virtual IP address that the service can be </p><p class="" style="white-space:pre-wrap;">accessed via from outside the cluster. </p></li></ul>
