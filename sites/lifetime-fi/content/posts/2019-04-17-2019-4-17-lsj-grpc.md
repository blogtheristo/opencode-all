<p class="" style="white-space:pre-wrap;">What is gRPC?</p>
<h3 style="white-space:pre-wrap;">gRPC - high-performance universal RPC framework</h3>
<p class="" style="white-space:pre-wrap;">gRPC is a modern RPC framework that can run in any environment. It can efficiently connect services in and across data centers with pluggable support for load balancing, tracing, health checking and authentication. It is also applicable in last mile of distributed computing to connect devices, mobile applications and browsers to backend services.</p>
<p class="" style="white-space:pre-wrap;">What is Protobuf?</p>
<h3 style="white-space:pre-wrap;">What are protocol buffers?</h3>
<p class="" style="white-space:pre-wrap;">Protocol buffers are Google's language-neutral, platform-neutral, extensible mechanism for serializing structured data – think XML, but smaller, faster, and simpler. You define how you want your data to be structured once, then you can use special generated source code to easily write and read your structured data to and from a variety of data streams and using a variety of languages.</p>
<p class="" style="white-space:pre-wrap;">Protocol buffers currently support generated code in Java, Python, Objective-C, and C++. With proto3 language version, you can also work with Dart, Go, Ruby, and C#. <a href="https://developers.google.com/protocol-buffers/docs/overview" target="_blank" rel="noopener">How do protocol buffers work?</a></p>
<p class="" style="white-space:pre-wrap;">gRPC messages are serialized using&nbsp;<span style="text-decoration:underline">Protobuf</span>, an efficient binary message format. Protobuf serializes very quickly on the server and client. Protobuf serialization results in small message payloads, important in limited bandwidth scenarios like mobile apps.</p>
<p class="" style="white-space:pre-wrap;"><a href="https://grpc.io/docs/guides/concepts.html" target="_blank" rel="noopener">gRPC Concepts</a> and <strong>recommended scenarios</strong></p>
<p class="" style="white-space:pre-wrap;">gRPC is well suited to the following main usage scenarios:</p>
<ul data-rte-list="default">
<li>
<p class="" style="white-space:pre-wrap;"><strong>Microservices</strong>&nbsp;– gRPC is designed low latency and high throughput communication. gRPC is great for lightweight microservices where efficiency is critical.</p>
</li>
<li>
<p class="" style="white-space:pre-wrap;"><strong>Point-to-point real-time communication</strong>&nbsp;– gRPC has excellent support for bi-directional streaming. gRPC services can push messages in real-time without polling.</p>
</li>
<li>
<p class="" style="white-space:pre-wrap;"><a href="https://en.wikipedia.org/wiki/Polyglot_(computing)" target="_blank" rel="noopener"><strong>Polyglot computing </strong></a><strong>environments</strong>&nbsp;– gRPC tooling supports all popular development languages, making gRPC a good choice for multi-language environments.</p>
</li>
<li>
<p class="" style="white-space:pre-wrap;"><strong>Network constrained environments</strong>&nbsp;– gRPC messages are serialized with Protobuf, a lightweight message format. A gRPC message is always smaller than an equivalent JSON message.</p>
</li>
<li>
<p class="" style="white-space:pre-wrap;"><a href="https://grpc.io/about/" target="_blank" rel="noopener">The main usage scenarios:</a></p>
<ul data-rte-list="default">
<li>
<p class="" style="white-space:pre-wrap;">Efficiently connecting polyglot services in <strong>microservices architecture</strong>.</p>
<ul data-rte-list="default">
<li>
<p class="" style="white-space:pre-wrap;">What are microservices?</p>
<p class="" style="white-space:pre-wrap;">Microservices - also known as the microservice architecture - is an architectural style that structures an application as a collection of services that are</p>
<ol data-rte-list="default">
<li>
<p class="" style="white-space:pre-wrap;">Highly maintainable and testable</p>
</li>
<li>
<p class="" style="white-space:pre-wrap;">Loosely coupled</p>
</li>
<li>
<p class="" style="white-space:pre-wrap;">Independently deployable</p>
</li>
<li>
<p class="" style="white-space:pre-wrap;">Organized around business capabilities.</p>
</li>
</ol>
<p class="" style="white-space:pre-wrap;">The microservice architecture enables the continuous delivery/deployment of large, complex applications. It also enables an organization to evolve its technology stack. <a href="https://microservices.io/" target="_blank" rel="noopener">Read more</a>.</p>
</li>
</ul>
</li>
<li>
<p class="" style="white-space:pre-wrap;">Connecting mobile devices, browser clients to backend services</p>
</li>
<li>
<p class="" style="white-space:pre-wrap;">Generating efficient client libraries</p>
</li>
</ul>
</li>
<li>
<p class="" style="white-space:pre-wrap;">Core Features that make gRPC awesome:</p>
<ul data-rte-list="default">
<li>
<p class="" style="white-space:pre-wrap;">Idiomatic client libraries in 10 languages</p>
</li>
<li>
<p class="" style="white-space:pre-wrap;">Highly efficient on wire and with a simple service definition framework</p>
</li>
<li>
<p class="" style="white-space:pre-wrap;">Bi-directional streaming with <a href="https://developers.google.com/web/fundamentals/performance/http2/">HTTP/2</a> based transport protocol.</p>
<ul data-rte-list="default">
<li>
<p class="" style="white-space:pre-wrap;">The primary goals for HTTP/2 protocol are </p>
<ul data-rte-list="default">
<li>
<p class="" style="white-space:pre-wrap;">to reduce latency by enabling full request and response multiplexing, </p>
</li>
<li>
<p class="" style="white-space:pre-wrap;">minimize protocol overhead via efficient compression of HTTP header fields, and </p>
</li>
<li>
<p class="" style="white-space:pre-wrap;">add support for request prioritization and server push. </p>
</li>
</ul>
</li>
<li>
<p class="" style="white-space:pre-wrap;">To implement these requirements, there is a large supporting cast of other protocol enhancements, such as new flow control, error handling, and upgrade mechanisms, but these are the most important features that every web developer should understand and leverage in their applications.</p>
</li>
</ul>
</li>
<li>
<p class="" style="white-space:pre-wrap;">Pluggable auth, tracing, load balancing and health checking</p>
</li>
</ul>
</li>
</ul>

All of a sudden, there are exponentially more services to monitor, numerous API surfaces to secure and a plethora of traffic to manage between services.</p>

<p class="" style="white-space:pre-wrap;">Istio, an open source tool to connect and manage microservices that is becoming an industry leading service-mesh for Kubernetes. </p>

<p class="" style="white-space:pre-wrap;">Cloud platforms provide a wealth of benefits for the organizations that use them. However, there’s no denying that adopting the cloud can put strains on DevOps teams. Developers must use microservices to architect for portability, meanwhile operators are managing extremely large hybrid and multi-cloud deployments. Istio lets you connect, secure, control, and observe services.</p>
<p class="" style="white-space:pre-wrap;">At a high level, Istio helps reduce the complexity of these deployments, and eases the strain on your development teams. It is a completely open source service mesh that layers transparently onto existing distributed applications. It is also a platform, including APIs that let it integrate into any logging platform, or telemetry or policy system. Istio’s diverse feature set lets you successfully, and efficiently, run a distributed microservice architecture, and provides a uniform way to secure, connect, and monitor microservices.</p>
<h2 style="white-space:pre-wrap;"><a href="https://istio.io/docs/concepts/what-is-istio/#what-is-a-service-mesh" target="_blank" rel="noopener">What is Service Mesh?</a></h2>
<p class="" style="white-space:pre-wrap;">Istio addresses the challenges developers and operators face as monolithic applications transition towards a distributed microservice architecture. To see how, it helps to take a more detailed look at Istio’s service mesh.</p>
<p class="" style="white-space:pre-wrap;">The term service mesh is used to describe the network of microservices that make up such applications and the interactions between them. As a service mesh grows in size and complexity, it can become harder to understand and manage. Its requirements can include discovery, load balancing, failure recovery, metrics, and monitoring. A service mesh also often has more complex operational requirements, like A/B testing, canary rollouts, rate limiting, access control, and end-to-end authentication.</p>
<p class="" style="white-space:pre-wrap;">Istio provides behavioral insights and operational control over the service mesh as a whole, offering a complete solution to satisfy the diverse requirements of microservice applications.</p>
