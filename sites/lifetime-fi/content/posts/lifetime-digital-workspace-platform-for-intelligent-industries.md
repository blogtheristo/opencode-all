<h2 style="white-space:pre-wrap;">Main capabilities of DWS Project Montreux</h2>
<h3 style="white-space:pre-wrap;">Project Montreux Building Process Quality Assurance</h3>
<p class="" style="white-space:pre-wrap;">The foundation of the DWS DevSecOps lies in the DevOps movement, wherein development and operations functions have merged to make deployments faster, safer, and more repeatable. Common DevOps practices include automated infrastructure build pipelines (CI/CD) and version-controlled manifests (GitOps) to make it easier to control cloud deployments. By managing software and infrastructure Quality Assurance (QA) Requirements in the release lifecycle, coding-able development teams save time manually reviewing code, allowing them to focus more on shipping the DWS features of Project Montreux.</p>
<p class="" style="white-space:pre-wrap;">As deployments to production speed up, however, many traditional cloud security concepts break down. With the use of containerized technologies, serverless Lambda functions, and IaC framework it is easier to maintain cloud security posture visibility and observability. By leveraging DevOps foundations, security and development teams can build security scanning and policy enforcement into automated pipelines. The ultimate goal with DevSecOps is to “shift cloud security left.” That means automating it and embedding it earlier into the development lifecycle so that actions can be taken earlier. Preventing risky deployments is a more proactive approach to traditional cloud security that often slows down development teams with deployment rollbacks and disruptive fixes. For DevSecOps to be successful for teams working to build and secure infrastructure, embracing existing tools and workflows is critical. The Management Team is committed to making it as simple, effective, and painless as possible to automate cloud security and integrate it seamlessly into release lifecycles of DWS Platform Build Process.</p>

<h1 style="white-space:pre-wrap;">The Architecture</h1>
<h2 style="white-space:pre-wrap;">DWS DevSecOps is the secure build environment on AWS with Bridgecrew</h2>
<h2 style="white-space:pre-wrap;">Architecture definitions for Project Montreux</h2>
<p class="" style="white-space:pre-wrap;">Project Montreux Build is Cloud Native platform, is created with Serverless First Design principles, is built as a set of resilient distributed applications and their functions that are loosely coupled microservices and architecture patterns that are developed and executed on multiple cloud platforms (Partners, Customers; on premises, Microsoft Azure, AWS, IBM Cloud, and so on).&nbsp;</p>
<p class="" style="white-space:pre-wrap;">DWS has a microservices based technology stack that runs serverless on AWS. DWS is based on infra as code containerization. DWS uses mostly managed services (AWS Lambda, Amazon ECS on AWS Fargate, RDS, DynamoDB, API Gateway, AppSync, CloudFront, OpenSearch, Kinesis, Cognito, AWS CloudFormation and Cloud DevSecOps for CloudFormation with Bridgecrew).</p>
<p class="" style="white-space:pre-wrap;">Our humble expectations for a core team members joining ( as seen on the applicant CV).</p>
<ul data-rte-list="default">
<li>
<p class="" style="white-space:pre-wrap;">Demonstrates professional experience on AWS backend services.</p>
</li>
<li>
<p class="" style="white-space:pre-wrap;">Impeccable command of modern NodeJS and Python languages.</p>
</li>
<li>
<p class="" style="white-space:pre-wrap;">Practical experience of applying microservice architecture patterns, Docker and containers orchestration (AWS Fargate , Kubernetes).</p>
</li>
<li>
<p class="" style="white-space:pre-wrap;">Worked on immutable infrastructure and applied IaC Terraform and AWS CDK CloudFormation (YAML).</p>
</li>
</ul>
<p class="" style="white-space:pre-wrap;">Project Montreux applications are written in various coding languages (Python, Go, JavaScript, YAML, JSON, Solidity) which are managed with Dapr.  Dapr is focused on helping developers in our certified partners core teams to build distributed applications, and it does not replace Service Meshes. Both Dapr and service meshes use the sidecar pattern and run alongside the application.&nbsp;</p>
<p class="" style="white-space:pre-wrap;">Project Montreux has Event Driven Architecture that uses APIs as front door for our modular services , containerization for Purpose-Build DBs, Automated build and deploy pipeline with DevSecOps IaC for the Industrial Client Deployment Scenarios(picture 1),</p>
<h1 style="white-space:pre-wrap;">Project Montreux Distributed Development Environment</h1>
<h2 style="white-space:pre-wrap;">Dapr principles used in Project Montreux</h2>
<p class="" style="white-space:pre-wrap;"><a href="https://docs.dapr.io/developing-applications/building-blocks/service-invocation/"><span style="text-decoration:underline">Service invocation</span></a> Perform direct, secure, service-to-service method calls. Dapr Using service invocation, dws4 applications can reliably and securely communicate with other applications using the standard <a href="https://grpc.io/">gRPC</a> or <a href="https://www.w3.org/Protocols/">HTTP</a> protocols.</p>
<p class="" style="white-space:pre-wrap;"><a href="https://docs.dapr.io/developing-applications/building-blocks/state-management/"><span style="text-decoration:underline">State management</span></a> Create long running stateful services.</p>
<p class="" style="white-space:pre-wrap;"><a href="https://docs.dapr.io/developing-applications/building-blocks/pubsub/"><span style="text-decoration:underline">Publish &amp; subscribe messaging</span></a> Secure, scalable messaging between services.</p>
<p class="" style="white-space:pre-wrap;"><a href="https://docs.dapr.io/developing-applications/building-blocks/bindings/"><span style="text-decoration:underline">Bindings</span></a> Interface with or be triggered from external systems.</p>
<p class="" style="white-space:pre-wrap;"><a href="https://docs.dapr.io/developing-applications/building-blocks/actors/"><span style="text-decoration:underline">Actors</span></a> Encapsulate code and data in reusable actor objects as a common microservices design pattern.</p>
<p class="" style="white-space:pre-wrap;"><a href="https://docs.dapr.io/developing-applications/building-blocks/observability/"><span style="text-decoration:underline">Observability</span></a> See and measure the message calls across components and networked services.</p>
<p class="" style="white-space:pre-wrap;"><a href="https://docs.dapr.io/developing-applications/building-blocks/secrets/"><span style="text-decoration:underline">Secrets management</span></a> Securely access secrets from your application.</p>
