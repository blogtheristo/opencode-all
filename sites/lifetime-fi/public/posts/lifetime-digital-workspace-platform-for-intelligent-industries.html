Project Montreux Building Process Quality Assurance

The foundation of the DWS DevSecOps lies in the DevOps movement, wherein development and operations functions have merged to make deployments faster, safer, and more repeatable. Common DevOps practices include automated infrastructure build pipelines (CI/CD) and version-controlled manifests (GitOps) to make it easier to control cloud deployments. By managing software and infrastructure Quality Assurance (QA) Requirements in the release lifecycle, coding-able development teams save time manually reviewing code, allowing them to focus more on shipping the DWS features of Project Montreux.

As deployments to production speed up, however, many traditional cloud security concepts break down. With the use of containerized technologies, serverless Lambda functions, and IaC framework it is easier to maintain cloud security posture visibility and observability. By leveraging DevOps foundations, security and development teams can build security scanning and policy enforcement into automated pipelines. The ultimate goal with DevSecOps is to “shift cloud security left.” That means automating it and embedding it earlier into the development lifecycle so that actions can be taken earlier. Preventing risky deployments is a more proactive approach to traditional cloud security that often slows down development teams with deployment rollbacks and disruptive fixes. For DevSecOps to be successful for teams working to build and secure infrastructure, embracing existing tools and workflows is critical. The Management Team is committed to making it as simple, effective, and painless as possible to automate cloud security and integrate it seamlessly into release lifecycles of DWS Platform Build Process.

The Architecture

DWS DevSecOps is the secure build environment on AWS with Bridgecrew

Architecture definitions for Project Montreux

Project Montreux Build is Cloud Native platform, is created with Serverless First Design principles, is built as a set of resilient distributed applications and their functions that are loosely coupled microservices and architecture patterns that are developed and executed on multiple cloud platforms (Partners, Customers; on premises, Microsoft Azure, AWS, IBM Cloud, and so on). 

DWS has a microservices based technology stack that runs serverless on AWS. DWS is based on infra as code containerization. DWS uses mostly managed services (AWS Lambda, Amazon ECS on AWS Fargate, RDS, DynamoDB, API Gateway, AppSync, CloudFront, OpenSearch, Kinesis, Cognito, AWS CloudFormation and Cloud DevSecOps for CloudFormation with Bridgecrew).

Our humble expectations for a core team members joining ( as seen on the applicant CV).

  • Demonstrates professional experience on AWS backend services.

  • Impeccable command of modern NodeJS and Python languages.

  • Practical experience of applying microservice architecture patterns, Docker and containers orchestration (AWS Fargate , Kubernetes).

  • Worked on immutable infrastructure and applied IaC Terraform and AWS CDK CloudFormation (YAML).

Project Montreux applications are written in various coding languages (Python, Go, JavaScript, YAML, JSON, Solidity) which are managed with Dapr. Dapr is focused on helping developers in our certified partners core teams to build distributed applications, and it does not replace Service Meshes. Both Dapr and service meshes use the sidecar pattern and run alongside the application. 

Project Montreux has Event Driven Architecture that uses APIs as front door for our modular services , containerization for Purpose-Build DBs, Automated build and deploy pipeline with DevSecOps IaC for the Industrial Client Deployment Scenarios(picture 1),

Dapr principles used in Project Montreux

Service invocation Perform direct, secure, service-to-service method calls. Dapr Using service invocation, dws4 applications can reliably and securely communicate with other applications using the standard gRPC or HTTP protocols.

State management Create long running stateful services.

Publish & subscribe messaging Secure, scalable messaging between services.

Bindings Interface with or be triggered from external systems.

Actors Encapsulate code and data in reusable actor objects as a common microservices design pattern.

Observability See and measure the message calls across components and networked services.
