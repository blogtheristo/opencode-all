DeepSeek V4 Flash on two GPUs.

700B+ parameters at native precision, hybrid GPU/CPU inference, and what it means for the box you own.

27 Jun 2026 · Written by Yannick Nick (@keennay) · edited by Risto Anton Paarni

The note, in one line

Yannick Nick ran DeepSeek V4 Flash at native FP4+FP8 precision on 2× RTX Pro 6000 GPUs + 256 GB DDR5 RAM, using KTransformers hybrid GPU/CPU inference. Context length: one million tokens. The model that “shouldn’t fit” fits — and returns benchmarks.

Good data from a good engineer.

Yannick Nick builds and upgrades systems for a living. He spent years running nationwide Video-On-Demand streaming backends across headless *nix servers, back when “cloud” was still becoming a buzzword. He has what we would call a systems engineer’s obsession: squeeze the maximum performance from resource-constrained hardware.

He pointed that obsession at DeepSeek V4 Flash — a Mixture-of-Experts model with 700B+ parameters — and made it run on two GPUs and a stack of DDR5.

And because a claim without numbers is a press release, here are the numbers.

The hardware

GPUs

2× RTX Pro 6000

System RAM

256 GB DDR5

Precision

FP4 + FP8

1M tokens

134 / 256

~200 GB

How KTransformers makes it fit

KTransformers gets less mention across the LLM inference ecosystem despite being listed for many popular models on HuggingFace. The KVCache-AI team provides a forked SGLang for hybrid GPU/CPU memory inference — split the MoE experts between GPU VRAM and system RAM, and the model runs where it otherwise would not.

134 of 256 experts live on GPU. The remaining 122 sit in system RAM. KTransformers can update GPU expert placement during inference from routing statistics collected during the prefill phase. The model adapts to its own traffic pattern, on hardware that costs a fraction of a hyperscale node.

What “hybrid” actually means here

GPU VRAM holds the hot experts. System RAM holds the rest. The split is configurable per layer. This is not quantization as a lossy shortcut — the model runs at its native mixed precision (FP4 + FP8). The tradeoff is latency on cold experts, not quality.

With 20.81 GB of available GPU memory after setup, Yannick found anything less too tight for agentic coding workloads. Trial and error is the price of admission — RTX Pro 6000 kernel support is still limited.

The benchmarks

100 prompts from the AlienKevin/SWE-ZERO-12M-trajectories dataset. 10 concurrent. ~8k input tokens, ~1k output tokens. Both Radix and Chunked Prefix Cache disabled — the absolute worst-case scenario.

Metric Mean Median
Prefill Batch Tokens 35,756.93 tok/s 652.90 tok/s
Time to First Token 20.698 s 12.714 s
Decode Batch Output 27.39 tok/s 20.63 tok/s

Twenty tokens per second on decode is not cloud speed. It is owned-hardware speed, at native precision, on a model with 700B+ parameters, with a million-token context window. That is the kind of tradeoff the sovereign edge is built on — control over throughput, jurisdiction over latency.

Why this matters for the owned box

We have said it before: the moat is not the model. The moat is the deployment. NVIDIA makes the silicon; KTransformers makes it fit; the customer owns the box.

Hybrid GPU/CPU inference is the supply-side enabler for on-prem agentic AI without hyperscale CapEx. Two GPUs and 256 GB of RAM is a workstation, not a data center. If a 700B+ MoE model runs at native precision on that workstation, the “you need the cloud for large models” argument weakens with every release.

“Necessity is the mother of invention,” Yannick writes. Local AI runners will keep finding creative ways to run intelligence — GPU/CPU memory offload, distributed inference, weight quantization, KV cache quantization, REAPs. Hardware prices climb. Ingenuity scales faster.

What comes next

Yannick plans hybrid GPU/CPU inference tests for MiniMax M3, GLM-5.2, and Kimi K2.7-Code. A detailed write-up on calculating expert-per-layer GPU counts, maximum token allocation, and GPU memory utilization for healthy agentic workloads will follow.
