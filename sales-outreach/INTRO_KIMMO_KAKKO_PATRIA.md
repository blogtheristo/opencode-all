## Supporting wedge (call content, not the commercial lead) — "KATAKRI has no control for an actor that isn't a person"

Kept from v1.0 and demoted deliberately: it opens a strong technical conversation but is too broad to be the commercial ask.

KATAKRI assesses whether an organisation can handle classified information: security management, physical security, technical information security. Every control assumes the actor is **a person with an identity, a clearance and a signature**, or a **system a person operates**.

An AI agent is neither. It acts, it touches documents, it moves data between systems, it can be changed after delivery — and the moment one runs inside an accredited facility, an auditor has to answer questions the criteria were not written for:

1. **Who is the actor?** An agent has no clearance, no personnel security assessment, no badge.
2. **What did it do, and can you prove it a year later?** Chat logs are not an audit trail.
3. **Who authorised the capability it used today** — given that the same model can be updated after deployment?
4. **Can you stop it?** Not "can you turn off the server" — can you revoke *that agent's* authority, now, and evidence that you did?
5. **Where did the data go?** A US-hosted assistant inside a defence factory is a CLOUD Act exposure surface over programme data.

Today most industrial organisations answer these with policy ("staff may not use AI tools for classified work") — which is unauditable, and already false in practice. **Shadow AI is the finding waiting to happen.** The wedge is to convert that policy answer into a technical, evidenced one.

**What DWS IQ Aegis brings to exactly that gap:**

| Auditor question              | DWS IQ mechanic                                                                                                        |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Who is the actor?             | **KYA (Know Your Agent)** — every agent has a verified identity and a trust score; no identity, no action.             |
| What did it do?               | **EU AI Act Article 12 logging** — every agent decision written to a tamper-evident record, retained and exportable.   |
| Who authorised the capability | Capability changes are authorised events with an actor and a timestamp, not a silent model update.                     |
| Can you stop it?              | **Kill-switch / leash-snap** on a single agent's authority — sub-5 ms, fleet under 50 ms — and the revocation is logged. |
| Where did the data go?        | Finnish hosting (europe-north1), single-tenant, **Firecracker MicroVM per agent**, no shared tenancy, no US cloud dependency. |

**Our own audit posture (credibility, not a claim about him):** PiTuKri audit completed; ISO 27001 targeted Q3 2026, SOC 2 Type II Q4 2026. We built the platform to be audited, which is why we are comfortable opening a conversation with an auditor rather than a buyer.

**What we are explicitly NOT pitching** (carried forward from the org record, still binding): drone autonomy, targeting, mission AI, anything in the NestOS lane, and any capability that would put DWS IQ into a controlled dual-use export category. This is enterprise and facility governance. Nothing in the first conversation requires classified information — and we do not ask for any.
