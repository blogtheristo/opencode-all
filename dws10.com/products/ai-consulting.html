The 6-Point Framework for Agentic Development

Based on industry-leading practices and our own experience using both Claude and Codex in production. We help your team implement each step.

1

Try the Tools — Actively, Not Passively

Designate an "agents captain" per team. Run agent hackathons. Many people get stuck thinking "could it do X?" instead of just trying. We help teams overcome initial inertia with structured adoption programs using both Claude Code and Codex.

2

Create Skills and AGENTS.md

Create and maintain an AGENTS.md (or CLAUDE.md) for every project. Update it whenever the agent struggles. Write reusable skills and commit them to a shared repository. We provide templates based on our battle-tested approach using Karpathy's agentic coding principles.

3

Make Internal Tools Agent-Accessible

Inventory your team's tools and make them accessible via CLI or MCP servers. We design MCP (Model Context Protocol) architectures that give agents access to your databases, ERP systems, and internal APIs — securely.

4

Structure Codebases to Be Agent-First

Write tests that are quick to run. Create high-quality interfaces between components. We help restructure codebases with TypeScript strict mode, Zod validation, and interface-first design — patterns that make code parseable by agents.

5

Say No to Slop

Managing AI-generated code at scale is an emerging problem. Ensure a human is accountable for every merge. Maintain the same review bar as human-written code. We set up code quality governance including pre-commit hooks, automated quality gates, and reviewer training.

6

Build Agent Infrastructure

Build observability for agent work. Track agent trajectories (not just committed code). Centrally manage agent tools and permissions. We implement monitoring, logging, and governance infrastructure — including EU AI Act Article 12 compliance.

The AI/IT Interdependence Problem — August 2026 Deadline

Why sovereignty is no longer optional

Modern AI systems don't operate in isolation. A single enterprise AI stack today interconnects: LLM APIs (Claude, OpenAI, Groq), cloud infrastructure (AWS, GCP, Azure — CLOUD Act jurisdiction), IoT/edge devices, ERP connectors (SAP, Dynamics), and agentic frameworks (MCP, A2A). Every layer of this stack is a potential compliance exposure point.

🇪🇺 EU AI Act — 2 Aug 2026

All AI systems touching EU residents require documented risk classification, technical specs, Article 12 logging, and human oversight. Non-compliance: up to €35M or 7% of global turnover.

🔒 CLOUD Act Exposure

US law can compel AWS, Azure, and GCP to hand over data — even in EU regions. If your AI inference runs on US hyperscalers, your EU customer data is not sovereign, regardless of GDPR clauses.

🕸️ AI/IT Interdependence

A compliant LLM on a non-compliant cloud is still non-compliant. Our consulting maps the full dependency chain — from model provider to edge device — and identifies every sovereignty and compliance gap.
