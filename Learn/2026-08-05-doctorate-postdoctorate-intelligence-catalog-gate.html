2026-08-05 — Doctorate/Post-Doctorate Intelligence Catalog Gate

Supersedes 2026-08-05-doctorate-strategy-research-in-progress.md (research now complete).

Origin

HIC’s own working framing from the loop: “doctorate-level” must mean reproducible inquiry and defensible evidence, while “post-doctorate-level” must mean discovering and validating new enterprise knowledge. This note converts that into a testable gate and runs it against the current 121-SKU product catalog. It deliberately reuses machinery already canonical in the repo rather than inventing new instruments — see “Grounding” below.

Strategy_Loop.md (claimed Copilot/DGX origin) remains unfound after a GitHub-wide search and a scheduled 10-minute recheck; see the superseded note for the full verification trail. Nothing in this note depends on that file existing.

Proposed Research Question (draft, not yet added to §1.2 — see HIC action)

RQ8 (proposed, catalog-scoped). What evidentiary and reproducibility criteria distinguish a DWS IQ product/service that merely generates enterprise output from one that constitutes doctorate-level (reproducible, defensibly-evidenced) or post-doctorate-level (novel, independently-validated) enterprise intelligence — and what fraction of the current product catalog clears that bar?

This is the KYA four-gate instrument applied one level down: not “is the standard falsifiable” but “does each product claim built on top of it clear the same bar.”

The gate

Doctorate-level (G1–G4, all required — reproducible inquiry + defensible evidence):

Gate Test Canonical anchor
G1 Reproducibility Same input reliably reproduces the same defensible output — independently re-derivable, not just a deterministic code path (new — no existing row)
G2 Evidence chain Full Article 12 reasoning lineage, audit-grade; not self-attested TRUTH row 29 (MGD), row 35 (KYA-S1)
G3 Falsifiability An independent conformance check can fail the output KYA SPEC §9 / four-gate #2
G4 Provenance persistence Versioned, revocable, chain-terminating record survives the single run KYA-S1 Bronze/Silver/Gold SLA

Post-doctorate-level (G5–G6, on top of G1–G4 — discovering + validating new enterprise knowledge):

Gate Test
G5 Novelty Output contains a claim not already contained in its inputs (synthesis, not retrieval/summarization)
G6 Independent validation The novel claim is checked against ground truth or an independent verifier before surfacing, not generated-and-shown

Test result: 121-SKU catalog against G1–G4

Source: dws10.com/config/products.json (121 SKUs, byte-identical to the landing-pages/ mirror — dual-folder sync intact).

  • 29 / 121 SKUs carry any evidence-trail language (audit / attestation / signed / verified / watermark) in their product definition — the only candidates for G2.
  • 92 / 121 SKUs carry none — fail G2 outright by omission.
  • Of the 29 candidates, G3 fails catalog-wide: they rest on KYA, and KYA’s own spec admits no conformance suite exists — a SKU cannot clear a gate its evidence layer hasn’t cleared yet.
  • G4 is catalog-wide aspirational: the Bronze/Silver/Gold SLA it depends on is still in public comment (closes 04.11.2026).
  • Finding: 0 of 121 SKUs currently clear the full doctorate-level gate. Not a product-logic defect — the evidence layer underneath (KYA) hasn’t cleared its own four gates, so every downstream claim inherits that gap.

Candidate set (29 SKUs) — blocked only on KYA reaching its own gates, not on product logic

DWS-AEGIS-PILOT-001, DWS-AEGIS-IMPL-001, DWS-CLIMATE-001, DWS-IQ-006, DWS-IQ-FREE-2026, FH-SIGN-001, FH-CMS-001, FH-SKILL-T3, CMP-T0/T1/T2, CMP-OC-STD/ENT, SS-T0/T1/T2, SS-OC-ENT, MO-T0/T1/T2, MO-OC-ENT, QG-T1/T2, SEO-T1/T2, GTM-T3, HSE-T3, AIS-EU-SOV-OC, plus the T2 tier of the ED/SG/LOG/SOV/CSAT/LF/CS bundle family that carries “audit” language.

  • Nearly all consulting/training/coaching SKUs: consulting-hourly, consulting-fit55, aws-consultancy, m365-consultancy, business-mentor-30, ai-koulutus-3d, claude-code-coaching-* (4 SKUs), lean-project, ai-consultant-day, firehorse-coach, ai-consulting-agentic
  • Edge hardware resale SKUs: edge-node-gn100, LF-JETSON-*, LF-DGX-SPARK, LF-IGX-ORIN, LF-NVIDIA-INSTALL
  • Sovereign DB / cloud-migration consulting: DWS-SOVEREIGN-DB-001, sovereignty-cloud-consulting
  • Marketing/comms/design/IT SKUs: firehorse-flow, omnichannel-multimodal, FH-OMNI-001, professional-web-pages, secure-email-proton, firehorse-data-services, digital-design-gold, cloud-ready-teams, devops-lead
  • Most single-domain agent SKUs below Pro tier: Emissions Data, Schedule Genius, Logistics, Customer Sat, Lead Feedback, Competitor Surveillance, Deepwiki Extractor, Viability, Themis Coordinator (T1)
  • Bundle/report/misc: LIFETIME-BUNDLE-2026, FH-RPT-001, FLEET-VIP-001, DWS-US/EU-STARTER/PILOT, LAND-* overlay bundles not already listed above, AIS-OUTCOME-PILOT, DWS365-CMP-T3, AC365-T3

Caveat, stated plainly so the list isn’t misread: several “does-not-meet” SKUs were never meant to carry an evidence-chain claim — hardware resale and human-delivered consulting are not intelligence claims by design, and “no evidence language” on those is correct, not a defect. The gate applies to SKUs that claim an intelligence outcome. First remediation step is tagging each SKU with whether it makes an intelligence claim at all, before treating absence of evidence language as a finding.
