DWS_THESIS_STANDARD.md — Content & Scope

v1.0 — ~490 lines across 11 sections + 2 appendices

Core Sections

  1. §1: The Four Files — Names and scope of the sacred quartet (V3Thesis_EN, V3Thesis_FI, PHD_FIREHORSE_EN, PHD_FIREHORSE_FI) with a table clarifying master's thesis = implementation evidence + product decisions (Metropolia), PhD thesis = scientific framing + market signals (LUT).
  2. §1.2: Content Scope Rule — Copied verbatim from CLAUDE.md to make it canonical here too, establishing that implementation evidence routes to master's thesis and scientific framing to PhD thesis.
  3. §2: Change Types — Three categories:
    • Category A (Additive/GREEN): Wholly new sections triggering HIC dialogue workflow
    • Category B (Lockstep-only/GREEN): Version bumps across all four files when any file changes
    • Category C (Corrective/YELLOW): Factual corrections requiring HIC spot-check
  4. §3: VERSION AND AGENT HISTORY Format — Exact field specifications to eliminate ambiguity and ensure every version is auditable.
  5. §4: HIC Dialogue Workflow (NEW) — The user's requested procedure formalized into six phases:
    • §4.1: Initiation — Agent drafts new section
    • §4.2: Submission — Agent shows full text in fenced code block to HIC and explicitly stops and waits
    • §4.3: Dialogue — HIC reads text and provides feedback
    • §4.4: Revision — Agent revises based on feedback
    • §4.5: Approval — HIC gives explicit "Status: APPROVED" sign-off
    • §4.6: Implementation — Agent commits to all four files in lockstep
  6. §5: Lockstep Version Bumping — Rules for when and how to bump all four files together.
  7. §6: Approval Gates Matrix — Who decides what and which gates are hard-blocking vs. advisory.
  8. §7: Citation & Sourcing Rules — Primary sources, secondary sources, field observations, and [UNVERIFIED] marking discipline.
  9. §8: Handling Obsolete Passages — Preservation rule per Rule 12 (Fail Loud): keep original, add new section, mark with supersession marker.
  10. §9: Learn/ HTML Versioning — Automatic regeneration via gen-thesis-html.cjs; retain all old versions.
  11. §10: Integration with Other DWS Standards — Cross-references to DWS_DOCUMENT_STANDARD.md, CLAUDE.md, DWS_TRUTH_STANDARD.md.

Why This Matters

Before this standard: Thesis changes relied on agent judgment and CLAUDE.md rules alone; no formal HIC review step before content was committed; ambiguity about version status.

After this standard: Every additive thesis change follows an explicit six-phase workflow; HIC sees the actual text before it's committed; dialogue feedback is solicited and incorporated before approval; approval is explicit and auditable.

This implements the HIC's explicit request to "print to HIC the changed text for dialog to improve the overall input before text becomes approved" — and provides the governance framework so it happens every time.
