DWS Skills & Commands Complete Guide

DWS IQ 6 provides 20 skills for AI coding agents — 17 slash commands in .claude/commands/ and 3 composable discipline skills in skills/. This guide explains every skill: what it does, when to use it, and how skills connect into workflows.

Audience: Human-in-the-loop (HIL) operators, developers using Claude Code, Cursor, or VS Code with DWS6.

1. Skill Types

TypeLocationInvocationPurpose
Slash commands.claude/commands/*.md/skill-name in Claude CodeAgent-executable workflows

Slash commands are interactive — the user triggers them with /command. They produce structured output.

Discipline skills are passive — agents discover and follow them automatically when relevant context is detected. They enforce process discipline.

2. gstack Development Workflow (Garry Tan)

The recommended development flow chains 6 skills in order:

/plan-ceo-review → /plan-eng-review → implement → /review → /ship → /retro

2.1 /plan-ceo-review

When: Starting a new feature, product, or major change.

Founder/CEO-level product review. Challenges scope, finds the "10-star product" hidden in the request, pressure-tests product-market fit. Asks "are we building the RIGHT thing?"

new feature should we build product direction

Output: GO / PIVOT / STOP decision with rationale.

2.2 /plan-eng-review

When: After CEO approval, before writing any code.

Engineering Manager architecture review. Locks data flow, diagrams, edge cases, test plan. Asks "are we building it the RIGHT WAY?"

architecture review technical design system design

Output: Locked implementation plan with data flow, API contracts, edge cases, test strategy.

2.3 /review

When: After implementation, before shipping.

Staff Engineer deep code review. Finds production-breaking bugs that would pass CI. Reviews logic, security (DWS Security Standard), performance, and correctness.

review my code code review is this safe to ship

Checks:

  • Correctness: logic errors, off-by-one, race conditions, null pointers
  • Security: no exec() with string interpolation, no CORS wildcards, SRI hashes
  • Performance: N+1 queries, memory leaks, unnecessary re-renders
  • DWS compliance: dual-folder sync, document standard, store format

2.4 /ship

When: After /review approval.

Release Engineer automated shipping. Syncs branch, runs tests, commits, pushes, and creates PR.

ship it create PR push and release

Flow: git pull → npm test → npm run build → git commit → git push → gh pr create

2.5 /browse

When: QA verification of UI changes, testing user flows, taking screenshots.

QA Engineer browser automation using agent-browser (Rust CDP). Navigates URLs, takes screenshots, verifies UI elements.

check the site take a screenshot verify the UI

2.6 /retro

When: Weekly (Fridays) or at end of a feature.

Engineering Manager weekly retrospective. Analyzes commits, velocity, work patterns, shipping cadence.

weekly retro what did we ship velocity report

3. Agent Discovery & Execution

3.1 /discover-agents

When: You don't know which agent handles a task.

Lists all DWS IQ agents matching a capability keyword. Searches across 25+ agents.

what agents are available find an agent for X list agents

3.2 /agent-run

When: You know the agent name and want to run it with specific input.

Runs any named DWS IQ agent with structured JSON input. Returns scored results.

Available agents: sitesense, material-oracle, compliance, schedule-genius, customer-sat, viability, deepwiki-extractor, emissions-data-analyst, construction, logistics, quality-gate, competitor-surveillance, seo-audit, lead-feedback.

3.3 /workflow

When: A task requires multiple agents working together.

Triggers multi-agent workflows that chain or parallelize several agents into a unified report.

Available workflows:

  • compliance-assessment — Full EU regulatory compliance (ETS + CBAM + CSRD + AI Act)
  • construction-full — Site safety + materials + scheduling + logistics
  • seo-pipeline — SEO audit + competitor analysis + content recommendations

4. EU Compliance & Analysis

4.1 /compliance-check

When: Assessing EU regulatory compliance for an industry or project.

Checks compliance against ETS, CBAM, CSRD, Fit for 55, and EU AI Act. Returns gap analysis with severity levels and remediation steps.

compliance check am I compliant CSRD status CBAM risk

Output: Compliance score (0-100), gaps by regulation, remediation priority matrix.

4.2 /carbon-analysis

When: Calculating embodied carbon for materials or construction projects.

Calculates embodied carbon per EN 15978 lifecycle stages (A1–D) using the Material Oracle agent. Uses validated emission factors from EU ETS benchmarks and IPCC 2006.

embodied carbon carbon footprint kgCO2e LCA

4.3 /sovereignty-assess

When: Evaluating database sovereignty for EU compliance.

Assesses CLOUD Act exposure, data residency, encryption, Row Level Security (RLS), and GDPR readiness.

sovereignty check CLOUD Act data residency

4.4 /site-safety

When: Assessing construction site safety conditions.

Uses the SiteSense agent to score conditions 0–100 with EN 13001 crane operation warnings.

site safety safety score crane operation wind speed risk

5. Operations & Infrastructure

5.1 /flow-status

When: Checking repository state, branch sync status, or merge targets.

Displays Git Flow status: branch type, remote sync, staged/unstaged changes, merge recommendations.

git status branch status am I synced

5.2 /email

When: Sending transactional emails, checking delivery status, or triggering digests.

Sends via Amazon SES (primary) or Resend (fallback). Always from risto@onelifetime.world (verified domain). Never uses noreply@.

send email email this report check delivery

5.3 /remote-control

When: Interacting with Lifetime Fleet edge devices or command centers.

Remote control for LWM Acer edge device, Control Room (field ops), Situation Room (strategic command).

remote control fleet status control room device health

6. Code Quality

6.1 /simplify

When: After completing a feature, or when code feels over-engineered.

Reviews changed code for duplicated logic, unnecessary complexity, dead code, OWASP Top 10 security issues, and performance anti-patterns. Automatically fixes issues found.

simplify clean up code reduce complexity refactor

Checks: DRY violations, unnecessary abstractions, dead code, XSS, SQL injection, command injection, CORS misconfiguration, N+1 queries, memory leaks.

7. Discipline Skills (Hard Gates)

These are not slash commands. They are process rules agents follow automatically. Located in skills/*/SKILL.md.

7.1 verification-gate

NO COMPLETION CLAIMS WITHOUT FRESH VERIFICATION EVIDENCE.

Location: skills/verification-gate/SKILL.md

Applies: Before marking todos complete, before git commit, before claiming bugs fixed, before saying "all tests pass."

If you're about to say...Do this instead
"should work"Run the test. Show output.
"probably fixed"Reproduce the bug. Show it's gone.
"seems correct"Run the linter. Show zero errors.
"I believe this passes"Run npm test. Paste the result.

7.2 design-first

NO IMPLEMENTATION WITHOUT DESIGN APPROVAL (3+ file changes).

Location: skills/design-first/SKILL.md

Process:

  1. Surface assumptions
  2. Present 2–3 approaches with tradeoffs
  3. Recommend one with rationale
  4. Wait for user approval

Skip when: Bug fixes (1–2 files), docs-only, dependency updates, user says "just do it."

7.3 dual-folder-sync

EVERY ROOT FOLDER CHANGE MUST SYNC TO LANDING-PAGES IN THE SAME COMMIT.

Location: skills/dual-folder-sync/SKILL.md

Root (source of truth)Production copy
dws10.com/landing-pages/dws10-com/
onelifetime.world/landing-pages/onelifetime-world/
dws6.com/landing-pages/dws6-com/
lifetime.fi/landing-pages/lifetime-fi/

Workflow: Edit root → copy to landing-pages → verify with diff → commit both together.

9. Creating New Skills

Slash Command

Create a new .md file in .claude/commands/ with YAML frontmatter:

---
name: my-skill
description: >
  Use when [specific trigger]. Does [specific action].
  Returns [specific output format].
---

CSO (Claude Search Optimization) rules:

  • Start with "Use when..." + specific symptoms/contexts
  • Include keywords agents would search for
  • Never summarize workflow in description (causes agents to skip reading full skill)
  • Keep under 500 characters

Discipline Skill

Create a new directory in skills/ with a SKILL.md. Content should be short (<150 words for frequent skills), start with a bold ALL-CAPS rule, include "When This Applies" and "Common Mistakes" sections.

Registration Checklist

  • Every new agent MUST have a corresponding skill in .claude/commands/
  • Update AGENTS.md Section 16 with the new skill
  • Update this guide (docs/DWS_SKILLS_GUIDE.md)
  • Regenerate Learn/ HTML
