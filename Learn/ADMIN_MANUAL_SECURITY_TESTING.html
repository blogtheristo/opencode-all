Interpreting Test Failures

Failure: test_red_blue_combination_blocked

Severity: 🔴 CRITICAL

Meaning: Core security control failed - Lethal Trifecta protection broken

Action: 1. STOP all deployments immediately 2. Review recent changes to src/mcp/security/tool_colors.py 3. Check if tool classifications were modified 4. Restore from last known good version 5. Investigate root cause 6. Re-test before proceeding

Failure: test_blacklist_blocks_webhook_site

Severity: 🔴 CRITICAL

Meaning: Known exfiltration vector not blocked

Action: 1. Check src/mcp/security/domain_validator.py 2. Verify BLACKLISTED_DOMAINS list intact 3. Check for accidental whitelist addition 4. Review security logs for exploitation attempts 5. Fix and re-test

Failure: test_csrf_protection (any test)

Severity: 🟡 HIGH

Meaning: CSRF protection may be compromised

Action: 1. Review src/web/middleware/csrf_protection.py 2. Check Flask middleware registration 3. Verify header validation logic 4. Test manually with browser dev tools 5. Fix and re-test

Failure: test_no_f_string_interpolation

Severity: 🟡 HIGH

Meaning: SQL injection vulnerability introduced

Action: 1. Run: python scripts/security/audit_sql_injection.py src/ 2. Identify files with f-strings in SQL 3. Refactor to use parameterized queries 4. Re-test

Adding New Security Tests

Test Template

"""
Tests for [New Security Feature]

Based on: [Reference URL]
"""

import pytest
from src.mcp.security.new_feature import NewFeature


class TestNewFeature:
    """Test [description]."""
    
    def test_positive_case(self):
        """[Feature] should allow valid input."""
        result = NewFeature.validate("valid_input")
        assert result is True
    
    def test_negative_case(self):
        """[Feature] should block invalid input."""
        result = NewFeature.validate("malicious_input")
        assert result is False
    
    def test_edge_case(self):
        """[Feature] should handle edge cases."""
        result = NewFeature.validate(None)
        assert result is False

Troubleshooting

Issue: Tests Pass Locally, Fail in CI

Cause: Environment differences

Solution:

# Check Python version
python --version  # Should be 3.11+

# Check installed packages
pip list | grep -E "pytest|Flask|requests"

# Run with same Python as CI
python3.11 -m pytest tests/security/ -v

Issue: Slow Test Execution

Cause: Network calls, database connections

Solution:

# Run with markers (if implemented)
python -m pytest tests/security/ -v -m "not slow"

# Profile tests
python -m pytest tests/security/ -v --durations=10

Issue: Flaky Tests

Cause: Race conditions, external dependencies

Solution: 1. Identify flaky test 2. Add retries (pytest-rerunfailures) 3. Mock external dependencies 4. Report to security team
