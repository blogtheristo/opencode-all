1. Overview

Purpose / Tarkoitus

This document establishes standardized naming conventions, metadata requirements, and versioning practices for all DWS6 project documentation, including workflows, documents, and code artifacts.

Tämä dokumentti määrittää standardoidut nimeämiskäytännöt, metatietovaatimukset ja versiointikäytännöt kaikille DWS6-projektin dokumenteille.

Principles / Periaatteet

  1. Traceability — Every document must be traceable to its creator and session
  2. Versioning — All documents must have clear version history
  3. Consistency — Same format across all document types
  4. Bilingual — Support for both English and Finnish
  5. Automation-Friendly — Machine-readable metadata

2. Document Header Standard

2.1 Required Header Block

ALL documents MUST include this header block at the top:

IMPORTANT: Pandoc Compatibility. Use *** (not ---) as delimiters around the VERSION AND AGENT HISTORY block. Pandoc interprets --- as YAML front matter, which causes parse errors.
# [Document Title]

***
# VERSION AND AGENT HISTORY

Version: X.Y

Sessions & Modifications:
  - Version: X.Y | Tool: [Tool Name] | Session: [ID] | Date: DD.MM.YYYY | Changes: [Description]

Session Links & References:
  - [Tool Name] ([Session ID]): [GitHub commit link]
  - View on GitHub: [Document link]

Document Status:
  - Created: DD.MM.YYYY
  - Last Modified: DD.MM.YYYY
  - Language: [Primary Language]
  - Languages Available: [List]
  - Publication Status: [ACTIVE / DRAFT / OUTDATED / ARCHIVED / DEPRECATED]

***

2.3 Publication Status Values

StatusMeaning
ACTIVEDocument is current and in use
DRAFTDocument is work in progress
OUTDATEDDocument is superseded, no longer maintained — pending archive
ARCHIVEDDocument is in docs/archive/, kept for historical reference
DEPRECATEDDocument is outdated and should not be used
UNDER REVIEWDocument is being reviewed

2.4 Document Lifecycle

DRAFT → ACTIVE → OUTDATED → ARCHIVED

3. Workflow Naming Standard

Format: [category]-[action]-[frequency]-v[version]-YYYY-MM-DD.yml

Example: security-scan-daily-v1-2025-12-30.yml

4. File Naming Conventions

Documents: [CATEGORY]_[NAME]_[LANGUAGE]_v[VERSION].md

SQL migrations: [number]_[ddmmyy]_[name].sql (e.g., 002_190126_firehorse_pilot.sql)

5. Version Control

Semantic versioning: MAJOR.MINOR — MAJOR for breaking changes, MINOR for additions/fixes.

6. Language Policy

Primary: English (EN). Finnish (FI) bilingual where required. 27 EU languages available via localization.

7. Metadata Requirements

All documents must include: version, tool, session ID, creation date, last-modified date, language, publication status.

8. PDF Standard

Use scripts/Generate-PDFs.ps1 (Pandoc) for PDF conversion. Use *** delimiters to avoid YAML parse errors.

9. Examples

See the source DWS_DOCUMENT_STANDARD.md §9 for full worked examples.

10. Knowledge Management & Storage

Decision matrix: use Supabase/database for structured, queryable data; use markdown for narrative, human-readable content.

11. Core Artifacts

Artifacts are versioned deliverables stored in artifacts/. Named: [product]-[type]-v[version]-[date].[ext].

12. Field Notes

Raw knowledge capture from real-world events. Stored in docs/field-notes/YYYY-MM-DD-slug.md. Published to Learn/ as HTML.

13. Enforcement

These standards apply equally to all tools — Claude Code, Cursor, VS Code, Codex, and human developers. No exceptions.

14. LLM Model Versioning

Track which AI model created/updated a document in the VERSION AND AGENT HISTORY block. Example: Claude Code (Sonnet 4.6).

15. Localization & Multi-Language Management

Support 27 EU languages. Finnish is primary secondary language. Use ISO 639-1 codes. Maintain glossary in docs/GLOSSARY.md.

17. Web Content Index Check NEW in v1.7

17.1 Purpose / Tarkoitus

Every document update MUST be followed by a web content check — a review of which live web pages are affected by the change.

Jokaisen dokumenttipäivityksen jälkeen TÄYTYY tehdä verkkosisältötarkistus.

17.2 Web Content Index

Location: docs/WEB_CONTENT_INDEX.md

This index maps every repository document to its corresponding web domain pages (dws10.com, dws6.com, onelifetime.world). It is the authoritative source for which web pages reflect which documents.

17.3 Post-Update Web Check Procedure

POST-UPDATE WEB CHECK

Step 1 — Look up document in docs/WEB_CONTENT_INDEX.md
Step 2 — For each mapped web page:
          a. Check: does page content reflect the doc change?
          b. If YES → no action, record "reviewed, no change"
          c. If NO  → update the HTML page (root first, then landing-pages/)
Step 3 — Record in PR description:
          "Web check: /page-name reviewed [no change | updated]"
Step 4 — Run: diff <root-page> <landing-pages-copy>  → must be empty

Skip condition: If the document is internal-only (marked — in all web columns), state "internal only" in PR description.

17.4 Agent Skill

Run /content-index check <document-path> to look up web impact for any document.

17.5 Content-Index Update Trigger

Update docs/WEB_CONTENT_INDEX.md when: a new document is created with web counterparts, a web page is launched/renamed/deleted, or a document is archived.

18. Learn HTML Generation NEW in v1.7

18.1 Rule / Sääntö

Every standards document update MUST produce a new versioned HTML artifact in Learn/.

This ensures AI agents and humans can read the latest standard in rendered HTML, and the morning briefing email links to current standards. Version history is preserved — never overwrite old versions.

18.2 Which Documents Require Learn/ HTML

DWS_BRAND_STANDARD.md✅ YesLearn/DWS_BRAND_STANDARD_v{VERSION}.html

18.3 Generation Method

Preferred: Pandoc

pandoc DWS_DOCUMENT_STANDARD.md \
  -f markdown -t html5 \
  --standalone \
  -o Learn/DWS_DOCUMENT_STANDARD_v1.7.html

18.4 Versioning Rules

  • NEVER overwrite an existing versioned file (e.g., _v1.6.html)
  • Always create a new file with the new version number
  • Also update the unversioned copy (Learn/DWS_DOCUMENT_STANDARD.html) — stable URL for agents

18.5 Morning Briefing Integration

The CEO Cockpit morning brief (06:00 Helsinki) includes a Learn Artifacts section showing HTML files modified in the last 7 days with direct GitHub links.

Links format: https://github.com/blogtheristo/dws6/blob/main/Learn/{filename}

18.6 Learn Artifact Naming

Learn/[DOCUMENT_SLUG]_v[MAJOR].[MINOR].html    ← versioned (permanent)
Learn/[DOCUMENT_SLUG].html                      ← latest (overwrite allowed)

Examples:
  Learn/DWS_DOCUMENT_STANDARD_v1.7.html   ← versioned
  Learn/DWS_DOCUMENT_STANDARD.html        ← latest (always current)
  Learn/WEB_CONTENT_INDEX_v1.0.html       ← versioned
  Learn/WEB_CONTENT_INDEX.html            ← latest
