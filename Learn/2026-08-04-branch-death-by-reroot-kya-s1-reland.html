Branch Death by Re-root — and the KYA-S1 Re-land — 2026-08-04

1. What the session was asked to do, and what it actually was

The instruction was three words: "fix merge errors."

There were no merge errors. There was no conflict to resolve. The branch carrying KYA-S1 (claude/study-palantir-mas2-MwtEw, PR #1317, closed 26.07.2026 as superseded) could not be merged into main for a reason git does not report as a conflict at all: the two histories had no common ancestor.

git merge-base HEAD origin/main   ->   (empty)
ahead:  4281 commits
behind:  709 commits

main was re-rooted between May and August 2026. Different root commit, disjoint graph. Every git merge attempt against it produces conflicts in every file that exists on both sides — which looks exactly like a bad merge, and invites hours of conflict resolution that can never converge. The prior session in this branch had in fact spent that time: it resolved six conflict hunks by hand against what it believed was an ordinary divergence, and pushed a merge commit that was already meaningless.

2. The insight, stated plainly

An empty git merge-base is a distinct diagnosis, and it is the first thing to check when a branch "won't merge."

The two conditions look identical at the point of pain — conflict markers everywhere — but the remedies are opposites:

Symptom Real cause Correct action
Conflicts in files both sides touched Ordinary divergence Resolve hunks, merge
Conflicts in every shared file, merge-base empty History re-rooted Do not resolve. Rebuild on current main.

Resolving conflicts in the second case is not slow — it is void. The output cannot be merged no matter how correct each hunk is. The cheap check (git merge-base A B returning nothing) should precede any conflict work.

Corollary for the PR backlog cleanup. The July backlog triage (docs/pr-cleanup/next-prompts-v2-bundle.md) reached the right verdict for this PR — "predates too much of current main to merge as-is" — but by judgement rather than by measurement. The merge-base check turns that judgement into a one-command test that any session can run on any stale PR, and it distinguishes "stale but mergeable" from "structurally dead" without reading a diff.

3. The second insight: unmerged work decays, silently

The KYA-S1 standard sat in an unmerged branch from 15 May to 4 August. Two facts inside it went stale while nobody could see them, because an unmerged branch is invisible to every review mechanism DWS has — the truth registry does not lint it, the calendar does not see its dates, and the standards library does not know it exists.

  1. A self-imposed deadline expired unserved. The standard opened a public-comment window of 15.05.2026–15.08.2026. Had it merged in August as written, it would have arrived with eleven days left on a window nobody had been able to comment in. Reset to 04.08.2026–04.11.2026, with the reason written into the document rather than the window quietly re-dated.
  2. The law moved underneath it. EU AI Act Article 50 began to apply on 2 August 2026 — two days before this re-land, eleven weeks after the text was written. The draft discussed labelling obligations in the future tense. It now states them as in force.

This is the same class of failure as the Outokumpu offer that lapsed unnoticed (Learning Standard v1.5 §4.1): a date sitting correctly inside a document that never speaks first. The new element is that a whole document can be in that state, not just a date within it.

6. HIC decisions

Q1 — Publish the KYA-S1 blog post, or park it? (two-way door on the text, ONE-WAY DOOR on publication)

The full text was shown in one fenced code block this session and is parked at docs/blog-drafts/kya-s1-one-signed-page.md with Status: DRAFT.

(RECOMMEND: approve the text now, publish in a following session.) Publication is one of the five acts §10.3 classifies one-way by default, and §10.3.1 requires a cooling gap — nothing irreversible ships in the session that conceived it. The text was re-drafted today, so approval today and publication in the next session satisfies both the draft gate and the cooling gap. The alternative — park the post entirely and ship only the standard — is defensible if you would rather the standard exist quietly until an assessor is lined up (see Q2), since the post's strongest line is "we claim no tier until someone signs," and that line is more credible once someone has.

Q2 — Who signs the first KYA-S1 attestation? (two-way door, but slow)

The standard's whole weight rests on §3: self-attestation is not evidence. DWS therefore claims no tier under its own standard. That is honest today and gets less comfortable the longer it stands — a published standard whose author qualifies for none of its tiers invites the obvious question.

(RECOMMEND: scope a Bronze-tier assessment against the existing KYA implementation, and treat the IDV domain as the pilot.) Bronze needs a third-party audit on at least one domain, and IDV is the domain where an external attestation already plausibly exists — the IDV providers named in §9 (Shufti, Veriff, Signicat) attest identity verification as their business. That converts "no tier" into "Bronze, IDV domain third-party attested" at the lowest marginal cost, and the remaining six domains can run on signed platform telemetry. The decision I need from you is whether to spend anything on this in 2026 at all, or to leave the standard tier-less through the comment window and revisit in Q1/2027.

9. Anti-patterns this session avoided (for the record)

  • Resolving conflicts that could never merge. Caught by checking merge-base before touching a hunk. The prior session in this branch did not, and its work was void.
  • Shipping a stale self-imposed deadline. The comment window was reset with the reason stated, rather than silently re-dated or allowed to expire unserved.
  • Publishing in the session that drafted. Cooling gap respected (§10.3.1).
  • Carrying old-main baggage into the rebuild. The dead branch's diff listed 31 files; only 4 were authored by this work. The other 27 were old main's content pulled in by the void merge and would have re-landed 709-commit-old versions of telemetry code, migrations and posts on top of current main. Only the 4 authored files were carried across.
