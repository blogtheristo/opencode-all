DGX Tunnel Startup Automation

Session Summary: Automated SSH tunnel establishment for OpenCode primary runtime to access DGX Spark agents service (localhost:3001). Eliminates manual tunnel setup; now integrated into session startup.

What Happened

OpenCode primary runtime (per CLAUDE.md) requires access to DGX Spark services via SSH tunnel. The dws-agents-local MCP endpoint (http://localhost:3001/mcp) was configured but unreachable—the SSH port forward was manual and fragile.

Problem: Each time OpenCode started, the tunnel was down. Had to manually run ssh -N -L 127.0.0.1:3001:127.0.0.1:3001 dgx-spark before the agents service was available.

Solution: Automated tunnel establishment as part of session startup via a new hook script.

Changes Made

1. Created .claude/hooks/dgx-tunnel-start.sh

  • Establishes SSH port forward: localhost:3001 ↔ dgx-spark:3001
  • Checks if tunnel already running (idempotent—won't create duplicates)
  • Verifies connectivity before returning success (netcat check, max 10s wait)
  • Handles cleanup and error states gracefully
  • Cross-platform port detection (netstat and ss fallback)

2. Updated .claude/hooks/session-start.sh

  • Added call to dgx-tunnel-start.sh at session initialization
  • Prefixes output with [DGX] for visibility and debugging
  • Non-blocking (errors logged but don't halt session)

3. Enabled dws-agents-local in opencode.json

  • Set "enabled": true on the remote MCP server config
  • Service now reachable when tunnel is live

Technical Detail

The tunnel script runs SSH in background with the following approach:

ssh -N -L 127.0.0.1:3001:127.0.0.1:3001 dgx-spark &
  • -N: Don't execute remote command (tunnel only)
  • -L 127.0.0.1:3001:127.0.0.1:3001: Forward local port 3001 to remote DGX port 3001
  • Background process; PID saved to /tmp/dgx-tunnel-3001.pid for cleanup
  • Polls with netcat until port is responsive (idempotent check on next session start)
  • Max wait: 10 seconds; fails fast if tunnel can't establish
