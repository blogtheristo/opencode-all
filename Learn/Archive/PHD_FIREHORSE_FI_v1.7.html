    • 1. Johdanto

    1.1 Tausta

    Yritysohjelmistomarkkinat vaativat yha enemman nopeaa tuotekehitysta, EU-saannosten noudattamista ja saumatonta asiakaskokemusta. Perinteinen verkkokauppatoiminta vaatii manuaalista puuttumista tuotepaivityksiin, syotehallintaan ja asiakastukeen. Firehorse-toimintamalli vastaa naihin haasteisiin tekoalynatiivilla automaatiolla Claude Codea kayttaen. Lifetime Oy operoi DWS10.com-alustaa, yritysverkkokauppaa joka palvelee ilmastoalykkyyden ratkaisuja, vaatimustenmukaisuusohjelmistoja ja ammattimaisia konsultointipalveluita 16:lle EU-saannellylle toimialalle. Alusta integroituu:
  • Google Merchant Center (Tili-ID: 8496329) tuotenakyvyydelle
  • Revolut Business kassan ja maksukasittelyn hoitamiseen
  • Claude Code automatisoituun kaupan yllapitoon Firehorse-mallin kautta
  • Cloudflare Pages staattiseen hostingiin EU-tietojen sijaintikriteerein

    4.3 Syotteen generointiputki

    javascript
// generate-feed.cjs tyonkulku
const generateFeed = () => {
  // 1. Lataa products.json
  const products = require('../config/products.json');

  // 2. Validoi pakolliset kentat
  validateProducts(products); // id, mpn, price, brand

  // 3. Generoi XML g:-nimiavaruudella
  let xml = generateXMLHeader();

  for (const product of products) {
    xml += generateProductItem(product);

    // 4. Lisaa checkout_link_template Revolutille
    const checkoutLink = product.revolutLink || 'https://revolut.me/lifetimeoy';
    xml += `<g:checkout_link_template>${checkoutLink}</g:checkout_link_template>`;
  }

  // 5. Kirjoita google-products.xml
  writeFile('google-products.xml', xml);
};

    13.1 Suunnitteluperiaate: valimuisti ratkaisee kaiken

    Firehorse-toimintamalli nojaa pitkakestoisiin tekoalyagenttisessioihin (Claude Code) kaupan hallintaan, tuotepaivityksiin ja vaatimustenmukaisuusautomaatioon. Prompt-valimuisti (prompt caching) on perustava suunnitteluperiaate, joka tekee naista sessioista taloudellisesti kannattavia. Lahde: Thariq Shihipar (Anthropic), "Lessons from Building Claude Code: Prompt Caching Is Everything" (2026). Ydinnakyma: Prompt-valimuisti kayttaa uudelleen laskentatuloksia aiemmista API-kierroksista etuliitesovituksen (prefix matching) avulla. API tallentaa valimuistiin kaiken pyynton alusta kunkin `cache_control`-katkaisupisteen kohdalle. Korkea valimuistin osumisprosentti vahentaa kustannuksia ja viivetta merkittavasti.

    14. Yrityksen monivuokralainen agenttiarkkitehtuuri

    14.1 Toimialakohtainen avoimen LLM:n valinta

    Yksikään avoin LLM ei ole optimaalinen kaikille 16 EU-toimialalle, joita DWS IQ palvelee. Jokaisella toimialavertikaalilla on oma sääntelykieli, toimialaosaamisvaatimukset ja rakenteellisen tulosteen tarpeet. `AgentConfig.model`-kenttä on jo agenttikohtainen, joten jokainen konkreettinen agentti voidaan konfiguroida eri koulutetulla Lifetime World Model (LWM) -mallilla + avoimella LLM:llä, jatkuvalla vertailuarvioinnilla.     14.2 Tuo omat agentit (BYOA) -arkkitehtuuri

    Yritysasiakkaat tuovat omat tekoälyagenttinsa työskentelemään DWS IQ:ssa. Tässä osiossa käytetään NCC:tä (pohjoismainen rakennusyhtiö) havainnollistavana tapauksena. NCC:n agenttiekosysteemi: | Agenttilähde | Määrä | Esimerkit | |-------------|-------|----------| | NCC:n sisäiset | 7 | Hankinta, Turvallisuus, BIM, Kestävyys, Kustannusarvio, Laatu, Projektisuunnittelu | | Urakoitsijoiden agentit | 14 | LVI-urakoitsija, Sähkö, Betonitoimittaja, Terästoimittaja, Ikkunavalmistaja, Eristys jne. | | DWS IQ -alusta | 3 | Vaatimustenmukaisuuslaskenta, Firehorse-raportti, Hiililaskuri | | Yhteensä | 24 | Kaikki yhdistetty A2A + MCP -protokollilla | Vuokralaiskohtainen Lifetime World Model (LWM): Lifetime World Model on yrityksen oppimiskerros, joka sijaitsee valitun avoimen LLM:n päällä. Se ei ole pelkästään hienosäädetty malli — se on strateginen tiedustelukerros, joka:
  • Hienosäätää yrityksen dataa ja sääntelyä — sisäistää asiakkaan operatiivisen datan, toimialastandardit ja EU-sääntelykontekstin luodakseen toimialakohtaista älykkyyttä, jota geneeriset LLM:t eivät pysty tarjoamaan
  • Optimoi markkina-arvon — oppii jatkuvasti vaatimustenmukaisuuden tuloksista, energiatehokkuustuloksista ja operatiivisista mittareista tunnistaakseen arvonluontimahdollisuuksia
  • Varmistaa kilpailuedun moniagenttityökaluilla — yhdistämällä vuokralaiskohtaisen tietämyksen moniagenttien orkestrointiin (A2A + MCP), LWM muuttaa raaan tekoälykyvykkyyden korvaamattomaksi operatiiviseksi voimavaraksi
    • Jokainen yritysvuokralainen saa oman LWM-instanssinsa:
  • Pohja-LLM: Valittu toimiala-arvioinnin perusteella (esim. Qwen 2.5 72B pohjoismaiseen rakentamiseen)
  • Hienosäädetty: Vuokralaisen omalla projektidatalla, toimialakoodeilla (RT-kortisto), sääntelykontekstilla
  • Liittimet: Tekla Structures (BIM), IFS Cloud (ERP), CO2data.fi (päästökertoimet)
  • Hiekkalaatikko: Vaihe 2 hetkelliskontteja (europe-north1) tai Vaihe 3 pysyviä (skaalassa)
    • Miksi 16 toimialaa tekee LWM:stä vahvemman: Jokainen alustalle lisätty toimiala tekee jokaisen olemassa olevan toimialan LWM:stä älykkäämmän anonymisoitujen vaatimustenmukaisuuskaavojen ristioppimisen kautta. Sementinvalmistuksessa todistettu hiilidioksidipäästöjen vähennystekniikka tuottaa siirrettävää tietoa rakentamiseen. Valmistuksen toimitusketjun Scope 3 -agentit siirtyvät elintarviketeollisuuteen. 16. toimialan asiakas hyötyy kaikkien 15 toimialan kertyneestä älykkyydestä — luoden vallihaudan, jota yksittäisen toimialan kilpailijat eivät voi replikoida.

    14.6.2 EMPO²: LWM-muistiarkkitehtuurin akateeminen perusta

    Artikkeli     "Exploratory Memory-Augmented LLM Agent via Hybrid On- and Off-Policy Optimization" (EMPO², arXiv:2602.23008, helmikuu 2026) tarjoaa akateemisen validoinnin DWS Lifetime World Model -hybridimuistisuunnittelulle. EMPO² yhdistää:
  • Parametrinen muisti (RL-päivitykset mallin painoihin) — vastaa DWS LWM:n hienosäätöä (QLoRA, Acer Veriton GN100)
  • Ei-parametrinen muisti (haku muistipuskurista) — vastaa DWS RAG:ta EU-säädöksistä + yritysdata (pgvector)
    • Tulokset: 128,6 % parannus GRPO-algoritmiin nähden ScienceWorldissa, 11,3 % WebShopissa. Keskeinen havainto:     muistilla koulutetut mallit ovat vahvoja myös ilman muistia päättelyaikana — validoiden DWS-strategian asteittain upottaa domaintieto LWM-painoihin samalla kun RAG toimii varamekanismina.
