Where DWS differs from the reference model

DWS adds

  • Jurisdiction as a routing input. Every model call is chosen by sovereignty tier (T1–T5) and room, with a no-cloud-fallback rule for Defence. The reference model treats hosting as a vendor list.
  • Plant as a layer. Control Room and Situation Room run at a site or in a fleet vehicle, so Plant Capital and Perception Capital sit inside the architecture.
  • Agent identity before agent action. KYA+I scores each agent and Themis signs each tool call. Leash snap stops a session.
  • Outcome metric. Monthly Governed Decisions (MGD) and Customer-Retained Capital (CRC) measure what the stack delivers.

The reference model has, DWS lacks

  • Typed ontology runtime. Objects, links and actions as executable, permissioned types. DWS has the vocabulary in ONTOLOGY.md, not the runtime.
  • System-wide branching. Test an agent or ontology change on a branch of live data before promotion.
  • One model gateway and catalogue. Single entry for enablement, usage tracking and rate limits per tenant.
  • Evaluation suites as a release gate. DWS has eval runners but no gate or dashboard.
  • Release channels per tenant. DWS update lanes are specified, deploy workflows disabled.
