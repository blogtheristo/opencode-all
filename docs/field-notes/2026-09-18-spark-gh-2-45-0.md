## The Story

1. HIC on `gn100-cb5d` ran the GitHub CLI Linux apt recipe: `curl` keyring to `/usr/share/keyrings/githubcli-archive-keyring.gpg` (`dd` 4528 bytes), wrote `github-cli.list`, then `sudo apt update` and `sudo apt install gh -y`.
2. `apt update` fetched `https://cli.github.com/packages stable InRelease`. That source was already present earlier the same day (Hit during docker-ce apt).
3. `apt install gh` printed **already the newest version (`2.45.0-1ubuntu0.3+esm3`)**. 0 upgraded, 0 newly installed.
4. `+esm3` is Ubuntu Pro/ESM, not a GitHub-published package. Current GitHub install docs use `/etc/apt/keyrings/` + `wget`; this paste used the older `/usr/share/keyrings/` + `curl` + `dd` path. GitHub rotated the Linux repo PGP key on 5.09.2026 — rewriting the keyring can still be the useful part of this paste.
5. GitHub CLI maintainers (Nov 2025, `cli/cli` `docs/install_linux.md`): community **2.45.x / 2.46.x** is **broken** (deprecated GitHub APIs). Spark is on 2.45.0 until policy explains why cli.github.com did not win.

## The Insight

Adding GitHub's apt repo is not the same as running GitHub's `gh`. Apt stayed on Ubuntu ESM. Do not force-upgrade without `apt-cache policy gh`.
