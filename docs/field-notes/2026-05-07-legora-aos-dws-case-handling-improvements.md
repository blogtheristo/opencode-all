## 1. What Legora AOS Does

Legora introduced the **Agentic Operating System (AOS)** — a runtime for running legal AI agents as first-class citizens on client matters (cases). Key capabilities:

| Legora AOS Feature            | What it means                                                                                |
| ----------------------------- | -------------------------------------------------------------------------------------------- |
| **Case as the OS primitive**  | Every unit of legal work is a _matter/case_; agents, docs, memory, deadlines all hang off it |
| **Persistent agent sessions** | Agents stay alive across sessions — they remember the case, not just the last message        |
| **Parallel agent dispatch**   | Multiple specialist agents (research, drafting, review) run concurrently on the same case    |
| **Human-in-the-loop gates**   | High-stakes actions (filing, signing) require explicit human approval before execution       |
| **Audit-by-default**          | Every agent action logged to the case record — admissible, explainable, auditable            |
| **Deadline engine**           | Calendar-aware; agents surface risks when deadlines compress                                 |
| **Document lifecycle**        | Docs are first-class case artefacts: draft → review → signed, all tied to the case           |

The strategic insight: **the "OS" is not the agents, it's the case context that holds them together.** Without a unified case entity, agents are isolated scripts.

## 2. DWS6 Current State — What We Have

The codebase scan reveals **5 parallel domain-specific state machines** that each behave like cases but don't talk to each other:

| Domain          | Entity                  | States                                                      |
| --------------- | ----------------------- | ----------------------------------------------------------- |
| Sales           | `Lead`                  | New → Cold_1_Sent → Engaged → Meeting_Booked → Disqualified |
| Contracts       | `Proposal` / `Contract` | Draft → Sent → Under_Review → Accepted/Rejected             |
| Documents       | `document_status` (DMS) | draft → in_review → approved → archived                     |
| ERP integration | `SyncOperation`         | pending → in_progress → completed / failed                  |
| Compliance      | Assessment (ad hoc)     | scored inline, no persistent state                          |

**50+ agents** exist (`Themis` for legal/ethics, `ChronosAgent` for deadlines, `Auditor` for audit trail, `Mnemosyne` for memory) — but they run _session-scoped_, not _case-scoped_.

**Temporal.io** workflow specs are generated by ChronosAgent but never executed — the workflow engine is in-process only.

**Missing entirely:**

- A unified `Case` table
- `caseId` in `AgentContext`
- Cross-domain case linking (one customer = one Lead + one Compliance Assessment + one Contract)
- Persistent case memory (pgvector exists but not wired per-case)
- Case lifecycle hooks for domain events

## 3. The Gap — DWS vs. Legora AOS

```
Legora AOS:   Case ──┬── Agents (parallel, persistent, case-scoped)
                     ├── Memory (per-case, semantic)
                     ├── Documents (lifecycle tied to case)
                     ├── Deadlines (calendar-aware)
                     └── Audit trail (per-case, admissible)

DWS6 today:   Lead ──── (sales agents)
              Contract ── (contract agents)
              Sync ────── (ERP agents)
              Compliance ─ (compliance agents)
              ↑ No bridge. Same customer, 4 different IDs.
```

## 4. Improvement Map — Legora Pattern → DWS Action

### 4.1 Introduce the `Case` entity (highest leverage)

A single Supabase table that stitches existing silos together:

```sql
create table public.cases (
  id           uuid primary key default gen_random_uuid(),
  org_id       uuid not null references organizations(id),
  title        text not null,
  type         text not null,     -- 'compliance', 'sales', 'erp-sync', 'contract'
  status       text not null,     -- 'open' | 'in_progress' | 'pending_approval' | 'closed'
  priority     text,              -- 'low' | 'medium' | 'high' | 'critical'
  lead_id      uuid references leads(id),
  contract_id  uuid,
  assessment_id uuid,
  assigned_agent text,            -- primary agent (e.g. 'themis', 'chronos')
  deadline_at  timestamptz,
  closed_at    timestamptz,
  metadata     jsonb default '{}',
  created_at   timestamptz default now(),
  updated_at   timestamptz default now()
);

-- Enable RLS (mandatory per DWS Data Standard)
alter table public.cases enable row level security;
```

**Effort:** 1 migration + 1 route file. Existing entities link via FK — no rewrite.

### 4.2 Add `caseId` to `AgentContext`

In `src/agents/types.ts`, extend `AgentContext`:

```typescript
export interface AgentContext {
  projectId: string;
  userId: string;
  orgId: string;
  sessionId: string;
  caseId?: string; // ← add this
  sandbox?: SandboxContext;
}
```

All 50+ agents inherit this immediately. Agents that receive a `caseId` can:

- Read case memory from pgvector
- Write observations back to the case log
- Surface case deadlines (ChronosAgent)
- Trigger approval gates when `priority === 'critical'`

**Effort:** 2-line change in types.ts. Zero breaking changes (optional field).

### 4.3 Wire persistent case memory via Mnemosyne + pgvector

`Mnemosyne` agent already exists but is session-scoped. Scope it to `caseId`:

```sql
create table public.case_memory (
  id          uuid primary key default gen_random_uuid(),
  case_id     uuid not null references cases(id) on delete cascade,
  agent_name  text not null,
  content     text not null,
  embedding   vector(1536),
  created_at  timestamptz default now()
);
create index on case_memory using ivfflat (embedding vector_cosine_ops);
alter table public.case_memory enable row level security;
```

Mnemosyne writes to this table after each agent turn. At case start, retrieve top-k relevant memories via cosine similarity — agents resume with full case context even across sessions.

**Effort:** 1 migration + update Mnemosyne agent to accept/write `caseId`.

### 4.4 Wire Temporal.io (ChronosAgent already generates the specs)

ChronosAgent outputs Temporal.io workflow specs — they're just never executed. The missing piece:

```typescript
// src/services/temporal.service.ts (new, ~80 lines)
import { Client } from '@temporalio/client';

export async function startCaseWorkflow(caseId: string, workflowDef: WorkflowDefinition) {
  const client = new Client({ connection: ... });
  return client.workflow.start(workflowDef.name, {
    taskQueue: 'dws-cases',
    workflowId: `case-${caseId}`,
    args: [{ caseId, steps: workflowDef.steps }],
  });
}
```

This gives cases **durable execution** — a compliance assessment that takes 3 days survives server restarts, retries failed steps, and signals back to the case on completion.

**Effort:** ~80-line service file + Temporal worker registration.

### 4.5 Case lifecycle hooks for domain events

Extend the existing event bus to emit `case.*` events:

```typescript
export type CaseEvent =
  | { type: "case.opened"; caseId: string; orgId: string }
  | { type: "case.step_completed"; caseId: string; stepId: string; agentName: string }
  | { type: "case.approval_required"; caseId: string; action: string; riskLevel: string }
  | { type: "case.deadline_risk"; caseId: string; deadlineDays: number }
  | { type: "case.closed"; caseId: string; outcome: string };
```

ChronosAgent already tracks EU compliance deadlines — routing `case.deadline_risk` to the case owner is a one-step integration.

**Effort:** Add to existing event bus types (~20 lines).

### 4.6 Human-in-the-loop approval gate (DWS already has the policy)

`approval-required` governance policy already exists in the agent execution layer. Wire it to cases:

- When a case agent proposes an action with `riskLevel === 'high'`, emit `case.approval_required`
- Send email to `case.assigned_human` via the SES email service
- Block workflow continuation until `PATCH /cases/:id/approve` is called

No new infrastructure — just connect existing governance policy → case event → email queue → API approval.

## 5. Themis as DWS Case Coordinator

`Themis` (legal/ethics agent) is the natural **Case Coordinator** agent:

- Already handles legal/ethics reasoning
- Can be expanded to:
  - Accept a `caseId` on invocation
  - Read case history from `case_memory`
  - Dispatch sub-agents (`Chronos` for deadlines, `Auditor` for compliance log, `Mnemosyne` for context)
  - Route human approval gates
  - Close the case with a structured outcome

This maps exactly to Legora's AOS model: one coordinator agent owns the case, specialist agents execute steps.

## 7. What NOT to Copy from Legora

Legora's AOS is optimised for **legal work** — long-horizon, document-centric, human-review-heavy. DWS cases are industrial + compliance + sales. Avoid:

- Over-indexing on document workflow (DWS cases are often data + API, not PDFs)
- Blocking on human approval for routine compliance scoring (keep Themis autonomous for standard-risk cases)
- Replicating Legora's matter taxonomy — DWS case types map to DWS products, not legal practice areas

### File: `supabase/migrations/065_cases.sql`

```sql
-- Migration 065: Unified Case entity
-- Introduces public.cases — the "Case OS" primitive that links Lead, Contract,
-- Assessment, and any future domain entity under a single trackable unit.
--
-- Run with: supabase db push  OR  psql $DATABASE_URL -f 065_cases.sql
-- Rollback: DROP TABLE public.cases CASCADE;

BEGIN;

CREATE TABLE IF NOT EXISTS public.cases (
  id             uuid        PRIMARY KEY DEFAULT gen_random_uuid(),
  org_id         uuid        NOT NULL,
  title          text        NOT NULL,
  -- 'compliance' | 'sales' | 'erp-sync' | 'contract' | 'custom'
  type           text        NOT NULL,
  -- 'open' | 'in_progress' | 'pending_approval' | 'closed'
  status         text        NOT NULL DEFAULT 'open',
  -- 'low' | 'medium' | 'high' | 'critical'
  priority       text        NOT NULL DEFAULT 'medium',
  lead_id        uuid        REFERENCES public.leads(id) ON DELETE SET NULL,
  contract_id    uuid,
  assessment_id  uuid,
  -- primary responsible agent (e.g. 'themis', 'chronos', 'auditor')
  assigned_agent text,
  deadline_at    timestamptz,
  closed_at      timestamptz,
  metadata       jsonb       NOT NULL DEFAULT '{}',
  created_at     timestamptz NOT NULL DEFAULT now(),
  updated_at     timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS cases_org_id_idx   ON public.cases (org_id);
CREATE INDEX IF NOT EXISTS cases_status_idx   ON public.cases (status);
CREATE INDEX IF NOT EXISTS cases_lead_id_idx  ON public.cases (lead_id);
CREATE INDEX IF NOT EXISTS cases_deadline_idx ON public.cases (deadline_at) WHERE deadline_at IS NOT NULL;

CREATE OR REPLACE FUNCTION public.set_cases_updated_at()
RETURNS TRIGGER LANGUAGE plpgsql AS $$
BEGIN
  NEW.updated_at = now();
  RETURN NEW;
END;
$$;

DROP TRIGGER IF EXISTS cases_set_updated_at ON public.cases;
CREATE TRIGGER cases_set_updated_at
  BEFORE UPDATE ON public.cases
  FOR EACH ROW EXECUTE FUNCTION public.set_cases_updated_at();

ALTER TABLE public.cases ENABLE ROW LEVEL SECURITY;

CREATE POLICY "cases_select_own_org" ON public.cases
  FOR SELECT USING (org_id = (auth.jwt() ->> 'org_id')::uuid);

CREATE POLICY "cases_insert_own_org" ON public.cases
  FOR INSERT WITH CHECK (org_id = (auth.jwt() ->> 'org_id')::uuid);

CREATE POLICY "cases_update_own_org" ON public.cases
  FOR UPDATE USING (org_id = (auth.jwt() ->> 'org_id')::uuid);

COMMIT;
```

### File: `supabase/migrations/066_case_memory.sql`

```sql
-- Migration 066: Case memory table (pgvector, Mnemosyne-scoped per case)
-- Enables persistent semantic memory for agents operating within a case.
-- Requires: pgvector extension (already enabled via earlier migrations).
--
-- Run with: supabase db push  OR  psql $DATABASE_URL -f 066_case_memory.sql
-- Rollback: DROP TABLE public.case_memory CASCADE;

BEGIN;

CREATE TABLE IF NOT EXISTS public.case_memory (
  id          uuid        PRIMARY KEY DEFAULT gen_random_uuid(),
  case_id     uuid        NOT NULL REFERENCES public.cases(id) ON DELETE CASCADE,
  agent_name  text        NOT NULL,
  content     text        NOT NULL,
  embedding   vector(1536),
  created_at  timestamptz NOT NULL DEFAULT now()
);

-- IVFFlat index for cosine similarity search (top-k recall)
CREATE INDEX IF NOT EXISTS case_memory_embedding_idx
  ON public.case_memory USING ivfflat (embedding vector_cosine_ops)
  WITH (lists = 100);

CREATE INDEX IF NOT EXISTS case_memory_case_id_idx ON public.case_memory (case_id);

ALTER TABLE public.case_memory ENABLE ROW LEVEL SECURITY;

-- Access governed via the parent case's org_id
CREATE POLICY "case_memory_select_via_case" ON public.case_memory
  FOR SELECT USING (
    EXISTS (
      SELECT 1 FROM public.cases c
      WHERE c.id = case_id
        AND c.org_id = (auth.jwt() ->> 'org_id')::uuid
    )
  );

CREATE POLICY "case_memory_insert_via_case" ON public.case_memory
  FOR INSERT WITH CHECK (
    EXISTS (
      SELECT 1 FROM public.cases c
      WHERE c.id = case_id
        AND c.org_id = (auth.jwt() ->> 'org_id')::uuid
    )
  );

COMMIT;
```
