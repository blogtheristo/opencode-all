## Abstract

This thesis documents the design and implementation of a multi-agent AI architecture for enterprise climate compliance, built on the DWS IQ Platform. The system integrates Google's Agent-to-Agent (A2A) Protocol and Anthropic's Model Context Protocol (MCP) to enable cross-organizational AI collaboration for EU regulatory compliance (Fit for 55, CSRD, ETS, CBAM, EU AI Act). The architecture demonstrates how industrial enterprises can connect their own AI agents to DWS IQ's compliance calculation, Firehorse reporting, and carbon footprint services — moving beyond web-based marketing into real operational AI collaboration.

## 1. Introduction

### 1.1 Problem Statement

EU climate regulations (Fit for 55, CSRD, ETS, CBAM) require enterprises across 25+ industries to calculate, report, and reduce carbon emissions. Current solutions are siloed — each organization runs its own compliance tools without the ability to collaborate across supply chains, partners, or regulatory bodies at the agent level.

### 1.2 Research Question

How can a multi-agent AI architecture, based on open protocols (A2A and MCP), enable cross-organizational climate compliance automation for EU-regulated industrial enterprises?

### 1.3 Scope

- DWS IQ Platform Version 6 as the host platform
- 11 industrial verticals (construction, energy, manufacturing, logistics, healthcare, real estate, financial services, public sector, mining, shipbuilding, waste management)
- Google A2A Protocol v0.3.0 for agent-to-agent communication
- Anthropic MCP for internal agent-tool integration
- EU regulations: Fit for 55, CSRD, ETS, CBAM, EU AI Act Article 12

## 2. Terminology

### 2.1 Protocol Terminology

| Term | Definition | Source |
|------|-----------|--------|
| **A2A (Agent-to-Agent)** | Open protocol enabling communication between autonomous AI agents across organizations. Agents communicate as agents (with reasoning), not as tools (with structured I/O). | Google / Linux Foundation |
| **MCP (Model Context Protocol)** | Protocol for connecting AI agents to tools, databases, and APIs. Provides structured input/output for deterministic operations. | Anthropic |
| **Agent Card** | JSON metadata document at `/.well-known/agent.json` describing an agent's identity, capabilities (skills), endpoint URL, and authentication requirements. Other agents read Agent Cards to discover collaborators. | A2A Protocol Spec |
| **Task** | The fundamental unit of work in A2A. Has a unique ID and progresses through a lifecycle: `submitted` → `working` → `completed` / `failed` / `input-required`. | A2A Protocol Spec |
| **Message** | A communication turn between client and remote agent. Has a role (`user` or `agent`) and contains one or more Parts. | A2A Protocol Spec |
| **Part** | The smallest unit of content within a Message or Artifact. Can contain text, file references, or structured data. | A2A Protocol Spec |
| **Artifact** | An output generated by an agent as a result of a Task — documents, reports, structured data, images. Composed of Parts. | A2A Protocol Spec |
| **Skill** | A capability advertised by an agent in its Agent Card. Clients select skills when creating Tasks. | A2A Protocol Spec |
| **Context ID** | Identifier that groups related Tasks and Messages for multi-turn conversation continuity. | A2A Protocol Spec |
| **Streaming** | Real-time incremental updates for Tasks via SSE (Server-Sent Events). | A2A Protocol Spec |
| **Agent Card Discovery** | Process where a client agent fetches `/.well-known/agent.json` from a remote agent's URL to learn its capabilities. | A2A Protocol Spec |

## 4. Implementation

### 4.1 DWS IQ as A2A Server

DWS IQ publishes an Agent Card at `https://api.dws10.com/.well-known/agent.json` describing three primary skills:

1. **compliance-calculation** — Accepts emissions data, returns Fit for 55/CSRD/ETS scores
2. **firehorse-report** — Generates audit-ready compliance reports
3. **carbon-calculator** — Calculates Scope 1/2/3 carbon footprint

### 4.2 Python SDK Integration

```python
# Partner-side: connecting to DWS IQ via A2A
from a2a_sdk import A2AClient

# Discover DWS IQ agent
client = A2AClient("https://api.dws10.com")
agent_card = client.get_agent_card()

# Create a compliance calculation task
task = client.create_task(
    skill_id="compliance-calculation",
    message={
        "role": "user",
        "parts": [{
            "type": "text",
            "text": "Calculate Fit for 55 compliance for our Q4 2025 emissions data"
        }, {
            "type": "data",
            "data": {
                "scope1_tco2e": 1250.5,
                "scope2_tco2e": 890.3,
                "scope3_tco2e": 3420.1,
                "industry": "manufacturing",
                "country": "FI"
            }
        }]
    }
)

# Wait for completion
result = client.wait_for_task(task.id)
# result.artifacts contains compliance scores
```

### 4.3 Multi-Turn Workflow Example

For complex ESG workflows, the A2A protocol supports `input-required` state:

1. Partner agent sends initial emissions data
2. DWS IQ agent asks for clarification (e.g., "Which ETS sectors apply?")
3. Partner agent responds with additional context
4. DWS IQ agent completes calculation and returns Artifact

### 4.4 Validation with A2A Inspector

All DWS IQ A2A endpoints are validated using the [a2a-inspector](https://github.com/a2aproject/a2a-inspector) tool:

```bash
pip install a2a-inspector
a2a-inspector validate https://api.dws10.com/.well-known/agent.json
```

## 6. Security Considerations

- **Authentication:** OAuth 2.0 and API keys (defined in Agent Card)
- **Data residency:** All A2A traffic processed in EU (europe-north1, Finland)
- **Encryption:** TLS 1.3 for all agent communication
- **GDPR:** No personal data in A2A Tasks (only aggregated emissions data)
- **EU AI Act Article 12:** All A2A Tasks automatically logged with reasoning lineage
- **CLOUD Act Free:** EU-only infrastructure, no US CLOUD Act exposure
