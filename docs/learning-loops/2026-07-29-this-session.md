## Proposed Rule Edits

### Edit 1 — new shared principle: `docs/DWS_TRUTH_STANDARD.md` (or a grants-specific standard)

WHY: 2 events (the DIANA misattribution, the traction misattribution) both stem
from the same root cause — a founder-recalled external fact was used before it
was dated, sourced and quoted. One of these would have been a false statement
to a funding body if it had shipped.
RISK: adds friction — every "X told us Y" claim now needs a paper trail before
drafting, which can feel like distrust of the founder's memory.
TEST: next grant/investor document that cites a specific external party's
specific action does so with a dated citation already in hand at draft time,
not added afterward.

```diff
+ ## External-Attribution Rule (grants, investor material, funder correspondence)
+
+ Any claim of the form "[named external party] said/requested/confirmed/offered
+ [specific thing]" may only be DRAFTED after the dated, quotable source exists
+ in the repo (an email, a letter, a logged call note). If the source does not
+ yet exist, write a `[TO FILL]` placeholder and the exact question needed to
+ fill it — never draft the sentence on the assumption it will check out.
+ This applies with extra force when two similarly-named external programmes
+ or funders exist (e.g. a municipal fund vs. the international programme it
+ feeds into) — verify WHICH one before attributing an action to either.
```

### Edit 2 — `.claude/commands/truth-check.md` (correction: this rule already exists)

WHY: checked before proposing — the 2026-06-29 Edit 1 WAS applied (see

traction-claim drift recurred anyway, seven months after that rule landed,

grant-specific correspondence). The existing rule fixes stragglers within one
sweep; it does not tell the agent to check for a claim ALREADY diagnosed as
broken in an unrelated document before starting that sweep.
RISK: none — this extends an already-adopted rule rather than replacing it.
TEST: next canonical-number correction includes, before the sweep, a grep for
prior self-diagnoses of that number (rejection post-mortems, "Gap N" notes)
and the surface list is confirmed to include grant/investor/board docs, not
only catalog + public sites + sales.

```diff
+ Before verifying any single occurrence of a canonical business-fact claim
+ (customer count, MRR, agent count, industry count), first grep the repo for
+ prior INTERNAL self-diagnoses of that exact claim — investor-doc audits,
+ rejection post-mortems, "Gap N" notes, or session field-notes that already
+ flagged inconsistency. A recurring drift that was previously diagnosed and
+ never closed is higher-priority than a claim with no prior flag.
```
