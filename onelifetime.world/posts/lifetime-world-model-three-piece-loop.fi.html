Kolmiosainen silmukka valvomoille

23. kesäkuuta 2026 · Risto Anton Päärni · Helsinki, Suomi

Valvomo on enimmäkseen ihmisiä tuijottamassa näyttöjä, odottamassa hälytystä ja sitten tarttumassa valmiiksi kirjoitettuun korjaukseen. Lifetime World Model V1 on suunnitelma tämän työn seuraavalle muodolle: havaitse, kuvittele seuraava siirto, ehdota korjausta — ja pidä ihminen komennossa.

Tämä on tavoitearkkitehtuuri, ei julkaistu tuote eikä allekirjoitettu kumppanuus. Alla nimetyt järjestelmät ovat teknologia-arkkityyppejä, joita kohti suunnittelemme — eivät integroituja toimittajia.

Kolme roolia, yksi silmukka. Kukin vastaa toimivaa osaa referenssikoodissa.

1 · Havainto — ankkuri

Raaka, monimuotoinen telemetria — lämpötila, värähtely, tuuli, kuormitus — normalisoidaan yhdeksi hallituksi tilannekuvaksi, jota kutsumme tilavektoriksi (State Vector). Matematiikka on determinististä ja elää koodissa, joten tilannekuva on tarkastettavissa, ei arvattu. Tesla-tyylinen päästä päähän -aistipino on tässä arkkityyppi: signaali ensin, vähemmän hauraita käsin rakennettuja putkia.

2 · Mielikuvitus — hiekkalaatikko

Ennen mitään siirtoa simulaattori projisoi, mitä kukin ehdokastoiminto tekisi tilavektorille — hyödyn, jonka se voisi tuoda, suhteessa riskiin, jonka se lisäisi. NVIDIA Cosmos -luokan maailmanmalli on arkkityyppi fysiikkatietoiselle versiolle tästä. Referenssi toimittaa deterministisen sijaisen, ja se on rehellinen siitä, että kyse on sijaisesta.

3 · Toiminta — silmukkainsinööri

Kun havainto ja simulaatio ovat samaa mieltä optimoidusta polusta, agenttikerros — Claude Code -arkkityyppi — laatii muutoksen. Referenssissämme se toimii samoilla BaseAgent-primitiiveillä, joita muu alusta jo käyttää. Korkeimmalle sijoittunut toiminto palaa ehdotuksena: 

// world-model-loop.agent.ts — silmukka, deterministinen ja portitettu
const stateVector = buildStateVector(telemetry, { anomalyThreshold });
const rankedActions = this.rankCandidates(stateVector, candidates);
const selectedProposal = this.buildProposal(rankedActions, candidates);
// palauttaa { stateVector, rankedActions, selectedProposal, rewardUpdates }

Silmukka ei koskaan toteuta ehdotusta. Live-muutos kantaa aina ihmisportin, ja applied-kenttä on tyypitetty arvoon false, jottei ehdotusta voi erehtyä julkaisuksi: 

return {
  action,
  rankScore: top.rankScore,
  requiresHumanApproval: true,
  applied: false, // kovatyypitetty — silmukka ehdottaa, ihminen komentaa
  rationale,
};

Rehellinen osa

”Työntää koodia live-järjestelmään” on koko idean riskialttein lause, joten suunnittelimme sen pois alusta alkaen. Live-muutos pysyy ihmisen / KYA-portin takana. Valvomoautomaatio fyysisessä ympäristössä on EU:n tekoälyasetuksen mukaan suuririskistä: dokumentaatio, lokitus ja ihmisvalvonta ovat osa rakennetta — eivät myöhempi lisäys. Eikä mikään tästä ole Cosmos-, Tesla- tai Anthropic-kumppanuus; ne ovat viitepisteitä.

Silmukan sulkee palkkio

Silmukka oppii operaattorilta. Kun ihminen ohittaa ehdotetun toiminnon, ohitus kirjataan negatiivisena palkkiona ja sama toimintotyyppi sijoittuu seuraavalla kerralla alemmas. Se on läpinäkyvä preferenssipaino, ei musta laatikko — ja vain sellaista oppimista voi asettaa tilintarkastajan eteen.

Lyhyt versio

  • Havainto ankkuroi silmukan hallittuun, deterministiseen tilavektoriin.
  • Simulaattori kuvittelee kunkin toiminnon seuraukset ennen kuin mitään liikkuu.
  • Agenttikerros ehdottaa korjausta — ei koskaan toteuta sitä itse.
  • Operaattorin ohitukset opettavat silmukkaa, avoimesti.
  • Tavoitearkkitehtuuri tänään. Rehellinen siitä.

Lue seuraavaksi

  • Maailmanmallin neljä oppimisparadigmaa
  • Ontologia elää tiimin aivoissa
  • Mallisi ei voita kohinatasoasi
