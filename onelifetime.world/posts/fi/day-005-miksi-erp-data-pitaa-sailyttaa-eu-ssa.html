Miksi ERP-data pitaa sailyttaa EU:ssa

20. maaliskuuta 2026·Risto Anton·Lifetime Oy

Kun eurooppalainen yritys tallentaa ERP-datansa yhdysvaltalaisen pilvipalvelun palvelimelle, se altistaa liiketoimintakriittisen tiedon vieraan valtion lainkaytolle. CLOUD Act antaa Yhdysvaltain viranomaisille oikeuden vaatia dataa missa tahansa amerikkalaisen yrityksen hallinnassa olevalla palvelimella — riippumatta siita, missä palvelin fyysisesti sijaitsee.

CLOUD Act selkokielella

Clarifying Lawful Overseas Use of Data Act astui voimaan maaliskuussa 2018. Sen ydinviesti on yksinkertainen: jos dataa hallinnoi yhdysvaltalainen yritys (tai sen tytaryhtio), Yhdysvaltain viranomaiset voivat vaatia tietojen luovuttamista maarayksella — vaikka data sijaitsisi Frankfurtissa, Helsingissa tai Tukholmassa.

Tama koskee kaikkia suuria pilvipalveluja: AWS (Amazon), Azure (Microsoft), Google Cloud, Oracle Cloud. Naiden yritysten eurooppalainen data on CLOUD Actin piirissa.

Kaytannossa tama tarkoittaa, etta yhdysvaltalainen tuomioistuin voi maarata Microsoftin luovuttamaan suomalaisen valmistusyrityksen ERP-datan — tilaukset, hinnoittelun, toimittajatiedot, henkilostodatan — ilman, etta suomalainen yritys edes tietaa pyynnostan.

GDPR vs. CLOUD Act -ristiriita

GDPR kieltaa henkilotietojen siirron EU:n ulkopuolelle ilman asianmukaista suojaa. CLOUD Act vaatii tietojen luovuttamista. Nama kaksi lakia ovat ristiriidassa, eikä ristiriitaa ole ratkaistu juridisesti.

EU:n ja Yhdysvaltain valinen tietosuojakehys (Data Privacy Framework) kattaa osan ongelmasta, mutta sen tulevaisuus on epävarma. Schrems I ja Schrems II -paatokset kumosivat aiemmat vastaavat sopimukset (Safe Harbor, Privacy Shield). Kolmannen kumoamisen mahdollisuus on todellinen.

Yritys, joka luottaa pelkastaan DPF-kehykseen, ottaa juridisen riskin. Jos kehys kumotaan, datansiirto muuttuu laittomaksi yhdessa yossa — ja takautuvat sanktiot ovat mahdollisia.

Kaupallinen vakoilu -riski

CLOUD Act ei koske pelkastaan rikostutkintaa. FISA Section 702 mahdollistaa tiedustelutiedon keruun ulkomaisista kohteista — mukaan lukien eurooppalaiset yritykset. Edward Snowdenin paljastukset osoittivat, etta NSA kayttaa pilvipalveluiden dataa systemaattisesti.

Teolliselle yritykselle tama tarkoittaa, etta tuotekehitystiedot, hinnoittelustrategiat, toimittajasopimukset ja asiakastiedot voivat paatya kilpailijan — tai kilpailijamaan — tietoon. Tama ei ole salaliittoteoria vaan dokumentoitu todellisuus.

Eurooppalainen vaihtoehto

Suvereeni datainfrqastruktuuri tarkoittaa, etta data sailytetaan eurooppalaisen yrityksen hallinnoimilla palvelimilla, jotka sijaitsevat fyysisesti EU:n alueella ja jotka eivat ole CLOUD Actin piirissa.

DWS IQ -alusta kayttaa Supabase-tietokantaa Google Cloudin europe-north1 -alueella (Hamina, Suomi). Supabase on avoimen lahdekoodin alusta, jonka data pysyy EU:ssa. Hetzner (Helsinki) tarjoaa lisainfraa erityisen herkkaan dataan.

Reunalaskenta (edge computing) vie taman askeleen pidemmalle: NVIDIA Jetson Orin Nano -laite suorittaa tekoalymalleja paikallisesti, ilman etta data poistuu yrityksen tiloista. Kriittisimmat tekoalypaattelyt tapahtuvat omalla laitteistolla.

Viisi askelta kohti suvereenia dataa

1. Kartoita, missa datasi talla hetkella sijaitsee. Moni yritys ei tieda tarkalleen. 2. Tunnista CLOUD Act -altistus: kaytätko AWS:aa, Azurea tai Google Cloudia? 3. Priorisoi kriittinen data: ERP, henkilöstö, tuotekehitys, sopimukset. 4. Suunnittele migraatio eurooppalaiseen infraan vaiheittain. 5. Dokumentoi dataresidenssi osaksi vaatimustenmukaisuusraportointia.

Datasuvereniteetti ei ole ideologinen kannanotto — se on riskienhallintaa. Ja riski kasvaa joka vuosi.
