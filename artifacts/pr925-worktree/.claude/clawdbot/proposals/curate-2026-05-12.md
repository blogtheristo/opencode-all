## Proposed CLAUDE.md edits

### 1. Add an "Auto-Mode Trust Boundary" section

**Why:** The boundary is currently declared only in the SessionStart hook
output. Each session re-loads it as a system reminder, but it's not in the
canonical CLAUDE.md, so it can't be referenced from PR descriptions, can't
be diffed, and any change to the hook silently changes policy.

**Proposed insertion** (after "Non-Negotiable Rules", before "Source-of-Truth Rules"):

```markdown
## Auto-Mode Trust Boundary

When operating in auto-mode (Claude Code without per-tool prompts), the
SessionStart hook declares three zones. The canonical policy lives here;
the hook output must match this section.

- **GREEN — full auto:** Read, Edit, Write, lint, test, build, git on
  feature branches (e.g. `claude/*`, `feature/*`, `fix/*`).
- **YELLOW — auto + logged:** MCP tools, agent skills, Docker, `gh`/MCP
  GitHub calls, `git push`. Every YELLOW action is appended to
  `.claude/hooks/audit/`.
- **RED — BLOCKED, human required:** DB migrations, deploys, outbound
  email, thesis files, Store sync, secrets. Must be approved per-action
  by a human; tooling refuses to proceed otherwise.

Trust boundary classification of a file uses the regex patterns in
`scripts/clawdbot-scan.mjs` (`classifyPath`). If a new file pattern needs
a zone, update both the hook and the scanner in the same commit.
```

### 2. Tighten the "Script Automation Rule"

**Why:** The current rule says scheduled scripts go in
`scripts/{daily,weekly,hourly,on-deploy}/`. Observed during this build:
`scripts/daily/` is auto-discovered by `day-runner.sh` on DGX Spark. New
scripts in those folders run automatically. That's an unstated
prerequisite — anyone reading CLAUDE.md without knowing day-runner exists
would not realize they're shipping a cron job.

**Proposed amendment** (append to the existing rule):

> Scripts in `scripts/daily/` are auto-discovered and executed at 03:00–06:00 UTC
> by `day-runner.sh` on DGX Spark. No registration is needed and no GitHub
> Actions are involved — dropping a `.sh` or `.ts` file in `scripts/daily/`
> ships a daily cron job. State is tracked in `logs/day-runner-state.json`
> to prevent double-runs.
